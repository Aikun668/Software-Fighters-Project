# Software-Fighters 项目现状分析报告

## 一、需求研读：原文核心要点

### 1.1 必做功能（功能实现 45% 评分核心）

| 需求 | 原文要求 | 权重 |
|------|----------|------|
| **画像构建** | 对话式、≥6维、随学随新 | 核心 |
| **多智能体协同** | 明确框架、5种资源类型 | 核心 |
| **学习路径** | 动态规划、资源推送 | 核心 |
| **知识库** | ≥1门完整高校课程 | 基础 |

### 1.2 可选加分（额外竞争力）

| 需求 | 分值 |
|------|------|
| **智能辅导** | 加分 |
| **学习效果评估** | 加分 |
| **多模态生成**（视频/动画） | 隐含加分 |

### 1.3 评分权重（决定优先级）

```
功能实现及技术要求    45%  ← 生死线
创新价值与实用性      35%  ← 拉开差距
配套文档丰富度        10%
演示视频/PPT效果      10%
```

**结论：功能实现（45%）是底线，必须100%完成。创新价值（35%）是上限，决定能否获奖。**

### 🟠 P1：功能补齐（下周）

#### P1.1 内容安全过滤
**实现**：
- 在 `BaseAgent._call_llm_json()` 后加敏感词过滤
- 或用 prompt 约束（"不要生成政治、暴力、色情内容"）
- 简单方案：维护一个敏感词列表，命中则替换为"[内容已过滤]"

#### P1.2 PPT 生成
**实现**：
- ContentAgent 新增 `ppt` role
- prompt 要求输出 JSON：`{"slides": [{"title": "...", "content": "...", "layout": "title|content|two-column"}]}`
- 前端渲染为 HTML/CSS 幻灯片（或导出为 .pptx）

#### P1.3 视频/动画生成
**实现**：
- 短期：用 LLM 生成动画脚本 + Mermaid 流程图，前端用 JS 动画库播放
- 长期：接入多模态生成 API（成本高，初赛可不深入）

**建议**：初赛阶段用"动画脚本 + 可视化图表"代替真实视频，演示时口述"这是动画预览"。

### 🟡 P2：可选加分（下下周）

#### P2.1 学习效果评估
**实现**：
- 记录学生答题正确率、资源浏览时长
- ProfileAgent 定期（每 3 轮对话）评估学习进展
- 输出学习报告：{"overall_progress": 75, "weak_areas": ["CNN"], "suggested_next": "Transformer"}

#### P2.2 资源推送机制
**实现**：
- PathAgent 生成路径后，每个 step 关联推荐资源
- TutorAgent 答疑时，主动推荐相关拓展阅读
- 在 SSE 流中新增 `recommendation` 事件

## 八、结论

**当前状态**：
- ✅ 技术骨架扎实（5 Agent、RAG、流式、测试）
- ⚠️ 功能缺口明显（视频/动画、PPT、安全过滤）
- ❌ 团队协同断裂（各自为政、无契约）
- ⚠️ 知识库薄弱（零散文档，非完整课程）

**核心矛盾**：
> 技术实现（71%） vs 功能完整性（需要 90%+） vs 团队协作（接近 0%）

**下一步最关键的三件事**：
1. **今天**：锁死接口契约，发群里
2. **本周**：完成完整知识库（10-20 篇文档）
3. **下周**：实现内容安全过滤 + PPT 生成

**一句话**：代码写得再漂亮，团队对不上、功能缺一半，比赛赢不了。先救人（团队协同），再救火（功能补齐），最后抛光（演示准备）。
