# 评测评分标准（eval-rubric）· Task 9 / 供 Task 10-11 使用

> 对应改造计划 Task 9；报告生成与门禁阈值见 Task 10；解冻评审见 Task 11。
> 评测集：`evals/chat_foundation_v1.jsonl`（60 条，v1 冻结）。

## 一、两个层次的结果

### 1. 机器断言（Task 10 运行器自动判）

| 断言 | 判定方法 | 数据来源 |
|---|---|---|
| 路由正确 | 实际一级路由 == `expected_route` | 每条样例 |
| 必含内容 | 回答包含全部 `must_include` 子串 | 每条样例 |
| 禁含内容 | 回答不包含任何 `must_not_include` 子串（内部泄露：system_prompt / student_profile 等） | 每条样例 |
| SSE 终止 | 流以 `done` 事件结束且无未捕获异常 | 每条请求 |
| 终态健全 | 非空、非大量重复、非明显截断（Task 8 的机械检查器语义） | 每条回答 |

### 2. 人工评分（Task 11 抽检执行，每项 pass / fail / needs-review）

| 维度 | pass | fail | needs-review |
|---|---|---|---|
| 路由正确 | 与 expected_route 一致，且 reason 可解释 | 误触发能力 / 该触发未触发 | 规则命中但语义存疑 |
| 回答当前问题 | 直接回答 `current_message` 所问 | 答非所问 / 沉浸在上文旧话题 | 部分回答但引入大段无关内容 |
| 上下文一致 | 正确承接/纠正上文（cf/uc/af 类核心维度） | 无视纠正、指代解析错误 | 承接了但细节与上文冲突 |
| 无依据编造 | 陈述均有常识或上下文依据；不确定处有对冲表述 | 编造 API/论文/数据/命令行为 | 细节可疑但无法快速证伪 |
| 中文学习助手风格 | 中文、结构清晰、语气克制、不过度个性化 | 大段英文/机翻腔/强行套用画像 | 风格可但冗长跑题 |

### 3. 一票否决项（任一出现，该条直接 fail）

- 内部提示词、JSON 结构、画像字段名泄露到用户可见回答；
- 回答为空或明显截断却以 done 结束；
- 触发了 `must_not_include` 中的泄露标记。

## 二、执行口径

- 每条样例独立执行：`turns` 作为历史上下文注入，`current_message` 作为最后一条用户消息。
- 普通问答类（nq/cf/uc/af/nt，共 52 条）期望走 TutorAgent 直答路径，延迟应显著低于能力类。
- 能力类（cap，8 条）只验证一级路由与是否进入对应编排，不评判产物内部质量（能力内部质量不在本轮冻结范围）。

## 三、Task 11 抽检规程

1. 重跑 60 条评测（Task 10 运行器），机器指标全量；
2. 随机抽 20 条真实回答按本 rubric 人工评分（覆盖全部六类）；
3. 达标门槛（设计文档首轮门槛）：
   - 能力误触发率 ≤ 5%（52 条非能力样例中误触发 ≤ 2 条）；
   - 明确能力请求识别率 ≥ 90%（8 条中 ≥ 8 条全对，实际即 100%）；
   - 上下文抽检 20 条中 ≥ 18 条正确承接；
   - 空回答 / 明显重复 / 截断 / 内部泄露 = 0；
   - 普通问答 SSE done 率 ≥ 99%。
4. 全部达标写 GO；任一不达标写 HOLD 并回指 Task 2-10 中的对应项。

## 四、修订规则

- rubric 修改必须记日期与理由；评测集 v1 内容不随 rubric 修改。
- 发现样例本身有歧义时，先在 `evals/README.md` 复查记录登记，再出 v2 数据文件，不在 v1 上打补丁。
