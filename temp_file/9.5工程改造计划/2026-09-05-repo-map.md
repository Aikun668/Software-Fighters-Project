## 二、与计划文档不符的事实（已证实，非猜测）

1. **前端聊天链路当前是死的**。真实 SSE 客户端 `api/chat.ts` 无任何调用方；主聊天页 `QuestionNavChat.vue` 是静态演示（浏览器实测：发送"什么是进程？"后 `/api` `/chat` 请求数为 0，页面只出现"静态演示模式"提示；截图 `2026-09-05-static-chat-demo-evidence.png`）。
2. **计划锚点 AITutor.vue 未挂载路由**（`/ai-tutor` → ModulePreview.vue），且其模拟回复已在 Task 1 前删除。Task 2 的"修改对象"应为 `QuestionNavChat.vue`（或新页面组件）+ `api/chat.ts`。
3. **前端实际请求路径是 `/api/chat`（Java）**，`/internal/api/chat` 是 Java→Python 的内部跳。计划所说"页面调用 POST /internal/api/chat"应理解为"页面经 Java 到达 `/internal/api/chat`"。
4. **SSE 事件类型错位**：Python 发 `content`（`StreamEventType.CONTENT`），而前端 `chat.ts` 只认 `token`/`done`/`error`；Java 转发层内部也按 `"token"` 累积正文。设计文档写的 `content/inquiry/recommendation/error/done` 与 Python 实现一致，与前端不一致。
5. **Java 把 50 条历史 + 全量画像注入每次请求**（ChatController chat() 第 3、4 步），是诊断文件"问题三/问题四"在代码层的实锤位置。
6. ai-service 存在独立的 `/internal/tutor/chat`（TutorChatRequest，messages 数组），与 `/internal/api/chat`（UnifiedChatRequest，message+messages）并存，两条入口语义不同。
