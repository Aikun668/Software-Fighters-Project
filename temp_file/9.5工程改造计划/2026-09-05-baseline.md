## 三、端到端实测（浏览器 + SSE）

### 1. 页面级（/question-nav-chat，真实浏览器）
- 操作：输入"什么是进程？"→ 点击发送。
- 结果：**零网络请求**（performance resource 过滤 `/api`、`/chat` 均为空）；页面仅显示"已记录你的问题，静态演示模式下会在这里展开回答"。
- 结论：主聊天页不连后端，为静态演示。证据截图：`2026-09-05-static-chat-demo-evidence.png`（同目录）。
- 页面→后端的首个 SSE 事件 / 终止事件：**无法测得**（链路在页面层断裂），详见 repo-map「与计划不符的事实」第 1 条。已改为在 ai-service 层直连实测（下节），并经静态证据补全 Java 跳（ChatController.java:58 / PythonClient.java:42,67）。

### 2. ai-service 层直连（`POST http://127.0.0.1:8001/internal/api/chat`）
普通问答 `{"user_id":1,"message":"什么是进程？","mode":"auto"}`：
- HTTP 200，`Content-Type: text/event-stream; charset=utf-8`。
- 事件序列：`center_start(stage=auto) → content → center_end → done`（done payload 含 `results[0].agent="TutorAgent"`、`intent="tutor_question"`）。
- 首/终事件齐全，流正常终止。

能力请求 `{"user_id":1,"message":"帮我出 5 道进程调度选择题","mode":"auto"}`：
- 正确路由至 `exercise` 中心（`center_start(stage=exercise)`）。
- **耗时约 3 分 40 秒**才出 `content → center_end → done`；期间连接靠 `:heartbeat` 注释保活。
- 注意：首次同样请求在客户端 180s 超时处截断——对真实用户而言等同"永远转圈"的风险场景（Task 3/延迟优化的输入）。
