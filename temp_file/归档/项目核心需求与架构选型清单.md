> 文档定位：基于当前代码库全景分析、GPT 多 Agent 体系评价、团队明确认可的模块范围，以及 AI 教育多智能体行业最佳实践，输出一份可直接落地的 Python AI 服务改造蓝图。
> 适用范围：仅约束 Python AI 服务侧；Java 后端与前端 UI 不在本次改造范围内。
> 分析依据：
> - 代码库实地分析（`internal_api.py`、agents、workflows、services、orchestration）

## 一、项目定位与核心目标

### 1.1 赛题目标

基于大模型构建**个性化资源生成与学习多智能体系统**，面向中国高校计算机/人工智能相关专业学生，提供可感知、可交互、可生成的学习辅导能力。

### 1.2 产品形态

以**对话辅导**为核心入口，学生可通过自然语言完成以下学习闭环：

- 明确学习目标 → 规划学习路径
- 提问与答疑 → 获得分层讲解
- 练习与批改 → 获得针对性反馈
- 生成学习资源 → 导出可沉淀资料
- 可视化知识结构 → 理解知识关联
- 追踪学习状态 → 获得数据反馈

## 五、架构选型：4 Centers + Router Agent + Result Agent

### 5.1 整体架构

```
用户输入
  │
  ▼
┌─────────────────────────────────────┐
│  Mode Priority Gate                 │  ← 手动模式优先级最高
│  （用户点了哪个 tab，就强制走哪条）    │
└─────────────────────────────────────┘
  │
  ▼
┌─────────────────────────────────────┐
│  Router Agent / IntentExtractor     │  ← auto 模式下识别单/多意图
│  输出：[mode1, mode2, ...]           │
└─────────────────────────────────────┘
  │
  ▼
┌─────────────────────────────────────┐
│  4 Centers                          │
│  ┌─────────────┐ ┌─────────────┐   │
│  │ Auto Center │ │ Plan Center │   │
│  │ 自动中心     │ │ 计划中心     │   │
│  └─────────────┘ └─────────────┘   │
│  ┌─────────────┐ ┌─────────────┐   │
│  │Resource Ctr │ │ Visual Ctr  │   │
│  │ 资源中心     │ │ 可视化中心   │   │
│  └─────────────┘ └─────────────┘   │
└─────────────────────────────────────┘
  │
  ▼
┌─────────────────────────────────────┐
│  Result Agent                       │  ← 聚合多中心结果，统一 SSE 输出
│  输出：文本 + 结构化数据 + 资源链接    │
└─────────────────────────────────────┘
```

### 5.2 各中心职责

#### 5.2.1 自动中心（Auto Center）

- **定位**：默认兜底中心，处理通用问答与意图不明的输入。
- **内部 Agent**：
  - `TutorAgent`：直接答疑
  - `DecomposeAgent`：复杂问题拆解
  - `ExplainAgent`：分层讲解
  - `VisualizePipeline`：自动判断是否需要图表
- **触发条件**：`mode == "auto"` 且意图为 `chat`/`explain`/`visualize`

#### 5.2.2 计划中心（Plan Center）

- **定位**：生成、调整、追问学习路径。
- **内部 Agent/Workflow**：
  - `LearningPathWorkflow`
  - `PathAgent`
  - `InquiryResolver`
- **触发条件**：`mode == "research"` 或意图包含 `learning_path`

#### 5.2.3 资源中心（Resource Center）

- **定位**：将学习内容沉淀为可导出资源。
- **内部 Agent**：
  - `ContentAgent`：生成课程文档
  - `CodeAgent`：生成代码示例
  - `PPTExporter` / PDF / Word / Image：导出资源
  - `MindMapAgent`（可选）：生成思维导图
- **触发条件**：`mode == "resource"` 或意图包含 `resource_gen`

#### 5.2.4 可视化中心（Visualization Center）

- **定位**：生成图表、知识图谱、结构可视化。
- **内部 Agent**：
  - `VisualizePipeline`：Mermaid / SVG / ChartJS / HTML
  - 知识图谱模块
- **触发条件**：意图包含 `visualize` 或 `knowledge_graph`

#### 5.2.5 Router Agent

- **职责**：根据手动模式 → 意图识别 → 多意图拆分的顺序，确定需要执行的中心列表。
- **输出**：`ExecutionPlan = [CenterTask(mode=..., input=..., context=...)]`

#### 5.2.6 Result Agent

- **职责**：
  - 按顺序执行 CenterTask
  - 维护跨中心上下文
  - 聚合最终输出为统一 SSE 事件流
  - 生成用户可见的 summary 与下一步建议
- **输出格式**：
  - `type`: text / plan / resource / exercise / visualization / summary / error
  - `payload`: 结构化数据
  - `agent`: 来源 Agent
  - `sequence`: 执行顺序

## 六、模式切换规则

### 6.1 优先级

1. **手动模式最高**：用户通过 UI tab 选择了模式（tutor/resource/solve/exercise/research），直接按该模式执行，跳过意图识别。
2. **自动模式识别**：`mode == "auto"` 时，调用 `IntentExtractor` 识别意图。
3. **不清晰时询问**：若置信度低或意图模糊，返回 `type=inquiry` 事件，询问用户。
4. **多意图顺序执行**：识别到多个意图时，按合理顺序串行执行（如：先 plan，再 exercise，再 resource）。

### 6.2 多意图示例

| 用户输入 | 识别意图 | 执行顺序 |
|----------|----------|----------|
| "帮我规划 Python 学习路径" | `[learning_path]` | Plan Center |
| "出 3 道 Python 基础题" | `[exercise_gen]` | Exercise Center |
| "规划 Python 路径并出 3 道题" | `[learning_path, exercise_gen]` | Plan → Exercise |
| "讲解快速排序并给个代码例子" | `[explain, code_example]` | Auto → Resource |
| "画一下知识图谱" | `[knowledge_graph]` | Visualization Center |

## 七、关键改造点

### 7.1 IntentExtractor 改造

- 当前：返回单一意图
- 目标：返回 `intents: List[IntentResult]`，支持置信度与多意图
- 增加 `is_clear: bool` 字段，用于触发 inquiry

### 7.2 `unified_chat` 改造

- 当前：单分支 `if effective_mode == "resource"`
- 目标：按 `ExecutionPlan` 循环执行多个 mode
- 每个 mode 完成后，更新上下文并进入下一个

### 7.3 新增 Centers 目录

```
ai-service/app/centers/
├── __init__.py
├── auto_center.py
├── plan_center.py
├── resource_center.py
├── visualization_center.py
├── router_agent.py
└── result_agent.py
```

### 7.4 Result Agent 输出规范

- 统一 SSE 事件格式
- 支持多中心结果聚合
- 生成最终 `summary` 与 `next_steps`

## 九、风险与约束

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| Java 后端不处理 research 模式 | 中 | plan 无法持久化 | Python 侧保证输出完整 plan；持久化由前端或后端后续处理 |
| Resource 生成耗时 2-3 分钟 | 高 | 前端 SSE 超时 | 前端设置 300s 以上超时；后端增加进度事件 |
| DeepSeek API 速率限制 | 高 | 并行 Agent 同时调用触发限流 | 引入请求队列 + 退避重试；P0 减少并行度 |
| 27 天时间紧张 | 高 | P1/P2 可能无法全部完成 | 严格守住 P0 边界；P2 可交付骨架 |
| 多意图顺序执行链路过长 | 中 | 总耗时不可控 | 限制最多 3 个意图；提供执行进度 |
| LLM 输出不稳定 | 中 | 结果不可复现 | 增加 fallback 与结构化校验 |
| 代码不能自曝项目来源 | 中 | 合规风险 | 提示词中不出现项目名称与外部来源 |
| Visualization Center 范围过大 | 中 | 编排可视化 + 内容可视化同时做可能超时 | 先做编排可视化（P1），内容可视化延后（P2） |
| Decompose Agent 精度问题 | 中 | LLM 分解可能不准确 | 先用基于知识图谱骨架的规则分解兜底 |

### 关键约束重申

- **不能修改 Java 后端代码**；Python 侧接口变更需与 Java 对齐 `UnifiedChatRequest` 协议。
- **前端代码当前不修改**；只给方案与接口约定。
- **提示词中不能出现项目名称与外部来源引用**。
- **LLM_PROVIDER=openai**（DeepSeek-v4-flash）。

## 十、结论

本项目采用 **4 Centers + Router Agent + Result Agent** 的多智能体中心架构，在保留现有 22 个 API 端点的基础上，通过新增一层 Center 编排壳，实现：

- 手动模式优先
- auto 模式多意图识别
- 多中心顺序执行
- 统一 SSE 输出聚合

### A.2 关键代码评估结论

- **代码架构合理**：`BaseAgent` + `BaseWorkflow` 抽象、LLM Provider 策略模式、LangGraph 编排，基础设施扎实。
- **API 入口过重**：`internal_api.py` 承载所有端点，需要从单体路由升级为分层架构。
- **已有 Agent 可高度复用**：12 个 Agent 中约 10 个可直接保留或轻度改造。
- **缺少核心编排层**：尚无独立的 Router Agent、Result Agent 和 Chat Center 状态管理。
- **Director 已具备三层路由**：规则快速路径 → Profile 过滤 → LLM fallback，与行业最佳实践一致。

## 附录 B：行业最佳实践借鉴

### B.1 宏观 → 微观分解

- **ACL 2026 "Filling Gaps"**：采用两层知识图谱（topic → skill），并按 Bloom 认知层级标注每个技能。
- **AgentTutor**：使用 LATS（Language Agent Tree Search）进行课程目标树搜索分解。
- **本项目做法**：`DecomposeAgent` 采用两阶段分解：先提取主题，再为每个主题标注 Bloom 层级 + 前置知识。

### B.2 多智能体系统典型 Agent 集合

| Agent | 本项目对应 | 优先级 |
|-------|-----------|--------|
| Planner/Curriculum Agent | `PathAgent` + `LearningPathWorkflow` | P0 |
| Diagnoser/Assessment Agent | 新建 `DiagnoseAgent`（BKT） | P1 |
| Tutor/Pedagogical Agent | `TutorAgent` | P0 |
| Content Generator | `ContentAgent` | P0 |
| Exercise Generator | `ExerciseAgent` | P0 |
| Reflection/Evaluation Agent | 新建 `ReflectionAgent` | P2 |
| Router/Orchestrator Agent | 新建 `RouterAgent`（复用 Director） | P0 |

### B.3 知识诊断实现路径

| 层级 | 方法 | 准确率 | 工作量 | 建议 |
|------|------|--------|--------|------|
| L1 | LLM 直接判断 | 70-75% | 1-2 天 | 快速 demo |
| L2 | BKT（贝叶斯知识追踪） | ~85% | 3-4 天 | **推荐** |
| L3 | ParLD / PELICAN 多 Agent 诊断 | 更高 | 5-7 天 | P2 可选 |

**推荐**：在 `DiagnoseAgent` 中集成 BKT，复用 `exercise_agent` 出题 + `evaluation_service` 判分。

### B.4 资源生成价值排序

| 资源类型 | 学生价值 | 实现工作量 | 建议 |
|----------|----------|------------|------|
| 交互式代码示例 | ★★★★★ | 低 | 强化 `CodeAgent` |
| 渐进式练习题 | ★★★★★ | 中 | `ExerciseAgent` 增加难度分层 |
| 概念讲解文档 | ★★★★☆ | 低 | `ContentAgent` 已覆盖 |
| 知识图谱/思维导图 | ★★★★☆ | 低 | `MindMapAgent` 已覆盖 |
| 闪卡 | ★★★★☆ | 低 | 合并到 `ExerciseAgent` |
| 小型练习项目 | ★★★★☆ | 中 | 新建 `ProjectAgent`（P2） |
| 视频/动画 | ★★★☆☆ | 高 | 低优先级 |

### B.5 Router Agent 最佳实践

- **规则优先**：80% 常见查询用关键词/规则快速路由。
- **Profile 过滤**：根据学生画像进一步筛选 Agent。
- **LLM fallback**：模糊查询用 LLM 做最终决策。
- **Relevance Pre-filter**：aliyassine22/Tutoring-Multi-AI-Agents-System 中先判断查询是否在课程范围内。
- **Ambiguity Detection**：shastripranav/orchestrator 中对 "help me"、"this"、"that" 等模糊词返回澄清。

## 附录 C：核心交互规则速查

| 场景 | 行为 |
|------|------|
| 用户手动选择模式 | 跳过意图识别，直接按该模式执行 |
| `mode == "auto"` 且意图清晰单一 | 执行对应 Center |
| `mode == "auto"` 且意图不清晰 | 返回 `type=inquiry` 事件询问用户 |
| `mode == "auto"` 且多个意图 | 按 `Plan → Auto → Resource → Exercise → Visualization` 顺序串行执行 |
| 执行链路超过 3 个意图 | 截断并提示用户分步进行 |
| 任一 Center 失败 | Result Agent 输出错误事件，继续执行后续 Center（除非致命错误） |
