## 四、技术方案（关键机制与坑）

### 4.1 D1 为什么成立：模块对象是 `sys.modules` 单例

`import internal_api as api` 把 `api` 绑定到**模块对象**；`api._get_xxx` 是**每次调用时的属性查找**。`monkeypatch.setattr(internal_api, "_get_xxx", stub)` 改的是同一个模块对象的属性 → 路由体通过 `api.` 取到 stub。✅

> 这也是为什么不能写 `from internal_api import _get_xxx`：那样拿到的是导入瞬间的函数引用，patch 包属性不会改变它。

### 4.2 循环导入：可控且已被既有代码证明

`__init__` 在装配区块**之后**才 `from internal_api import profile`；`profile.py` 顶部 `import internal_api as api` 此时 `internal_api` 已在 `sys.modules`（部分初始化，但工厂已定义）→ 绑定成功。函数体内的 `api._get_xxx` 在**调用时**解析，晚于初始化完成。✅

### 4.3 `_EXPORTS_DIR` 必须留在 `__init__`

`test_sse_shared_facilities_delegation.py::_tmp_exports` 用 `monkeypatch.setattr(internal_api, "_EXPORTS_DIR", str(tmp_path))`。若 `_EXPORTS_DIR` 定义在 `resources.py`，patch 包属性不会影响 `resources._EXPORTS_DIR`（模块全局）→ 3 个下载端点会去真实导出目录找文件 → 用例红。**故 `_EXPORTS_DIR` 定义在 `__init__`，`resources.py` 读 `api._EXPORTS_DIR`。**

### 4.4 `router` 聚合与 prefix

- 子模块 `router = APIRouter()`（无 prefix），装饰器照抄原路径（如 `/profile/chat`）。
- `__init__`：`router = APIRouter(prefix="/internal")` + `router.include_router(<sub>.router)` × 9。
- 最终 48 条路径与 `openapi.paths` 与拆包前**逐条相同** —— 由 Task 1 新增契约测试锁定。

### 4.5 re-export 清单（漏一个就红一个）

47 个路由函数名 + `router` + `sse_response` + `safe_export_path` + `sanitize_model` + `_EXPORTS_DIR` + 18 个 `_get_xxx` + 18 个 `_xxx_singleton` + 18 个 `_x_lock` + `_get_mock_flag` + `_sse_stream_chunks`。

### 4.6 防"旧模块影子"

删除 `internal_api.py` 后须清理 `__pycache__/internal_api.*.pyc`，避免陈旧缓存/同名模块残留造成"改了没生效"。写入 Task 2 的执行步骤。
