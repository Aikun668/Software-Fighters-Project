# P3-B3b 画像双层图 → 单层图（含行为变更验收）

- **日期**：2026-09-25 · **基线**：`2f81c0b`
- **范围**：`ProfileWorkflow`（外层 5 节点）与 `ProfileAgent`（内层 5 节点）合并为**单层管线**
- **定性**：⚠️ **行为变更轮**（激活了两个此前被静默跳过的画像质量节点）
- **决策**：由用户「开始」授权，AI 依证据判定为**激活**，理由见 §二

---

## 一、问题（GUIDE P3 / 约定文档 §5 偏离项 1）

合并前是**两层 LangGraph**：

```
ProfileWorkflow（生产入口，/profile/chat）
  extract → merge → completeness_check → response | complete
     │         │                              │
     └─────────┴──────────────────────────────┴── 逐节点转发内层同名节点

ProfileAgent（内层图，production 从未 run）
  extract → semantic_judge → merge → audit → respond
                 ▲                    ▲
                 └── 这两个节点没有任何生产路径可达 ──┘
```

即：**设计好的画像质量能力（语义去重 / 画像审计）被静默跳过**。

---

## 二、决策依据（为什么是「激活」而不是「删掉」）

| 事实 | 证据 |
|---|---|
| 两者都是**真能力**，且在验证脚本里被验证过 | `tests/verify_p2_p3_24_cases.py:260` 有用例「相似 weak_point 两次→semantic_judge 去重」 |
| `semantic_judge` 在生产装配下**具备执行条件** | `profile_agent.__init__` **无条件**构造 `self.judge_llm`（走 DeepSeek Flash），不依赖 `model_profile` |
| 成本有**预筛门控** | `DEDUP_PREFILTER = 0.45`：新条目无候选时**不调 LLM**，直接创建 |
| 执行频率有**间隔门控** | `AUDIT_MSG_INTERVAL = 20`：不足 20 条抽取消息直接返回；无 weak_points/interest 条目也直接返回 |
| 两者都 **fail-safe** | judge 异常 → `judge_result = {}` 回退 embedding；audit 无结果 → 返回 `{}` |
| 「合并」在本计划里的语义就是收敛到**一条管线** | 若把两个节点从图里删掉，那不是「合并」，而是「删能力」 |

> 反过来看，删掉它们会移除一个已被设计+验证的质量能力，代价比激活更大。

## 三、改了什么

```python
# app/workflows/profile_workflow.py（合并后）
graph.add_node("pipeline", self._pipeline_node)          # ← 委托 ProfileAgent.run()
graph.add_node("completeness_check", self._completeness_check_node)
graph.add_node("complete", self._complete_node)
graph.set_entry_point("pipeline")
graph.add_edge("pipeline", "completeness_check")
graph.add_conditional_edges("completeness_check", self._route_after_completeness_check,
                            {"response": END, "complete": "complete"})
```

- `pipeline` 直接 `await self.profile_agent.run(state)` —— 复用 Agent 的公开入口（与 P3-B3a 的「复用走公开 API」约定一致）
- 删除 3 个纯转发节点 `_extract_node` / `_merge_node` / `_response_node`
- 路由字符串仍为 `response` / `complete`（`_route_after_completeness_check` 及其测试**一字未改**）
- `ProfileAgent.build_graph` **未改动**（extract → semantic_judge → merge → audit → respond），故 `verify_*` 脚本的 `agent.run()` 语义不变

### 行为差异（逐条）

| 变化 | 用户可见影响 | 成本 |
|---|---|---|
| `semantic_judge` 开始执行 | 相似条目会被语义合并（质量↑） | 仅在 embedding 预筛命中候选时调一次 Flash |
| `audit` 开始执行 | 每 20 条抽取消息清理/更新画像条目 | 每 20 条一次 LLM |
| `respond` 由「仅不完整分支」变为「管线末节点」 | **无**（完整分支会被 `complete` 固定文案覆盖） | 完成那一轮多一次 LLM 调用 |
| `_postprocess_output` 出站安全扫描 | 无 | 画像路径多一次文本遍历 |

### 回退（一行）

把 `pipeline` 节点换回原 5 节点转发版（原实现见 `git show 2f81c0b:ai-service/app/workflows/profile_workflow.py`），
并把 `tests/test_profile_single_layer_contract.py` 一并回退即可。
