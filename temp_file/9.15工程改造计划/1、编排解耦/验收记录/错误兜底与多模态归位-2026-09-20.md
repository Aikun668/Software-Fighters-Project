## 一、摸底的首要结论：两件事的真实体量都比标题小

GUIDE 第 2/3 步的字面要求是「抽出统一错误」「抽出多模态消息构建」。摸底实测：

| 检查项 | 实测值 |
|---|---|
| `internal_api.py` 内 `except Exception` 总数 | 32 |
| 其中 JSON 兜底形状**完全一致**（`api_error` 信封） | 28 |
| SSE 端点手写 `json.dumps` 错误帧 | **2**（`profile_chat` / `inquiry_resolve_plan`） |
| 把**异常原文**回进响应体 | **1**（`eval_judge`） |
| 缺 `exc_info=True` | **26 / 32** |
| `main.py` 全局 `Exception` handler | **0（无）** |
| 14 个无 `try` 端点抛异常时的响应 | `500 text/plain: Internal Server Error` |
| 多模态代码在仓库内的位置 | **仅 `internal_api.py` 一处** |
| 多模态函数的调用点 | **0**（48 个端点无一调用；`UnifiedChatRequest.images` 声明于 `app/api/models.py:113` 但从未被读取） |

即「错误信封其实早就统一了」，真正的工作是 **三处漏网 + 一处真空白**；多模态则是**一段零调用的死代码**。

**这直接决定了本轮定性**：多模态只做「纯函数归位」，**不接线**；不借这轮顺手启用图片能力（用户明确约束）。

## 八、全局 500 兜底的三条语义保留（哈希级实测）

存证脚本 `ai-service/_accept_global_500.py`（未跟踪）在**同一个 `main.app`** 上只切换「全局 `Exception` handler 是否在册」这一个变量（`exception_handlers.pop` + `middleware_stack = None`），其余一律不动：

| case | BEFORE | AFTER | 判定 |
|---|---|---|---|
| `unhandled_json_endpoint`（`/internal/profile/workflow/status`，无 `try`） | `500 text/plain`，body `\nInternal Server Error`，`e41656eb…` | `500 application/json`，body `\n{"success":false,"errorCode":"INTERNAL_ERROR","error":"服务内部错误，请稍后重试"}`，`93d98d5a…` | ✅ **正是本轮要补的空白** |
| `unknown_route_404` | `404 application/json`，`37ec4665…` | 同上，`37ec4665…` | ✅ **HTTPException 语义未变** |
| `validation_error_400` | `400 application/json`，`eea85156…` | 同上，`eea85156…` | ✅ **参数校验语义未变** |
| `sse_success_profile_chat` | `200 text/event-stream`，`da65446c…` | 同上，`da65446c…` | ✅ **SSE 成功路径未变** |

### 机制说明（源码级）

`starlette 1.0.0` / `fastapi 0.136.1`：

1. `Starlette.build_middleware_stack()` 把 `key in (500, Exception)` 的 handler 装配到**最外层** `ServerErrorMiddleware`，其余进内层 `ExceptionMiddleware`。
2. 因此本 handler **只在异常逃过内层 `ExceptionMiddleware` 时才生效** —— `HTTPException`（404/405）与 `RequestValidationError` 在内层就被各自的专属 handler 接走，语义不受影响。
3. `ServerErrorMiddleware.__call__` 里 `if not response_started: await response(...)` 守卫，意味着 **SSE 流中途出错时不会补发第二个响应**，随后 `raise exc` 交还服务器记录。

（第 1、3 条已用 `inspect.getsource` 实地核对安装版本，不是凭记忆。）

## 十、契约中登记的既有缺口（**不是本契约认可的期望行为**）

`MM-A09_documents_known_mime_allowlist_bypass`

MIME 白名单的判定条件是 `img.find(";") > 0`。**不带分号的 data URI**（`data:image/svg+xml,<svg onload=alert(1)>`）取不到 `;`，判定整段被跳过，SVG 因此**绕过白名单被原样保留**。

- 实测确认：`build_multimodal_message("描述", ["data:image/svg+xml,<svg onload=alert(1)>"])` 保留了该 URL。
- 当前该函数**零调用**，缺口尚未暴露；**一旦接线（把 `body.images` 真正喂进聊天链路）就会变成活的风险**。
- 本轮定性为「归位不接线」，因此 `MM-A09` 锁定的是**现状**。**修复该缺口时本用例应当翻红**，届时删掉它、改在 `MM-A05b` 一类正向用例里锁新行为。
- 已在 `app/utils/multimodal.py` 模块 docstring 中登记。
