## 二、⚠️ 头号成果：一条**真实并发缺陷**被复现并修掉

### 2.1 缺陷

`BaseAgent.run` 把逐请求回调写进**实例属性** `self._current_on_token`（旧 `base_agent.py:131`），
`TutorAgent._respond_node` 从实例读（旧 `tutor_agent.py:358`）。
而 `/tutor/chat` 路径的 `TutorAgent` 是**长生命周期单例**（`internal_api._get_tutor_agent` → `_get_tutor_center`）
—— 并发请求会互相覆盖该属性。

### 2.2 复现取证（用 HEAD 版实现跑的）

把 `git show HEAD:ai-service/app/agents/base_agent.py`（实例属性实现）落成临时模块，
用与 `ST-A04` 相同的探针图并发跑两次 `run()`：

```
请求 A 收到的 token: []
请求 B 收到的 token: ['A', 'B']
[REPRODUCED] 旧实现（实例属性）在并发下会串流回调 -> 缺陷真实存在
```

**A 的 token 被送到了 B 的回调**（B 同时收到自己和 A 的）。

> 复用 `ChatCenter` 路径时没暴露，是因为那条路每次 `TutorAgent()` 新建（`auto_center.py:86`）；
> 但 `/tutor/chat` 走单例，缺陷成立。
> 验证脚本为一次性临时脚本，用后已删除。

### 2.3 修法与保证

```python
# base_agent.py
current_on_token: ContextVar = ContextVar("current_on_token", default=None)

async def run(self, input_state: dict) -> dict:
    on_token = input_state.pop("_on_token", None)
    token = current_on_token.set(on_token)
    try:
        result = await self._compiled_graph.ainvoke(input_state)
    finally:
        current_on_token.reset(token)
```

- **为什么不放 state**：LangGraph `ainvoke` 会丢弃 schema 外字段（旧注释已踩过）；
- **为什么不是实例属性**：单例 + 并发 → 串流（§2.2 已复现）；
- **为什么是 ContextVar**：按协程隔离，嵌套调用由 `set/reset` 配对保证。
- 单请求语义**逐字不变**：`ST-A05` 断言回调可用且运行后不残留。

## 十、复核发现：PLAN 存证的基准带日期，跨天会漂

清尾复跑时 PLAN 出现 **9 条中 2 条不一致**，查证过程与结论：

| 检查 | 结果 |
|---|---|
| 差异内容 | 仅 `"today":"2026-09-24"` → `"2026-09-25"`（`today` / `progress` 两个 case 的载荷） |
| case 名单 | `###` 行完全一致（9 个 case 均在） |
| 同日连跑两次 | **identical=True** |
| 结论 | **基准的日期敏感性**，与 P3-B3a 改动无关；SSE / GRAPH 两个 harness 不受影响（均 100% 一致） |

原因：`plan_endpoints.py` 用相对锚点（`TODAY`/`NOW`）构造**请求**，但**响应体里带服务端当天日期**，
而 harness 直接对 raw text 取 sha256 → 每日漂移。

**建议修法（未做，属独立小轮）**：哈希前做日期归一化，例如
`raw.replace(TODAY.isoformat(), "<TODAY>")` 后再取 sha256，并重生成一次基准。
> 在此之前，跑计划域存证请**与当日新跑的基准比**，或先做归一化 —— 否则每天都会误报那 2 条。
