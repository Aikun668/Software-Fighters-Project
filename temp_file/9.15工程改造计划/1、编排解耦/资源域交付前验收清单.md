## D. `/resources/generate` 真实 SSE 验收 ✅ 通过

> **模式说明**：本次验收采用两层证据：
> 1. **真实服务 + 真实 LLM 历史快照**（`ai-service/rg-sse.txt`，来自上一轮 session）
> 2. **同进程 ASGI HTTP/SSE 委派验收**（`ai-service/_accept_sse_harness.py` Case 1）
>
> 采用 (2) 的原因：当前 `_get_mock_flag()` 恒为 `False` 强制真实 LLM 路径，而当前 LLM key 已不可用，curl 真实服务的路径会立刻返回 `{"type": "error", "content": "无法判断..."}` + 空 done（这是环境限制，非资源域回归）。按用户原话"应使用同进程 ASGI HTTP 测试,或启动一个仅用于验收的临时 uvicorn harness,在该进程启动前完成 monkeypatch,再用 curl 请求。不得修改生产 Workflow 装配"，本节采用同进程 ASGI 路径。

### 证据 1：真实 LLM 历史快照（rg-sse.txt）

请求：`POST /internal/resources/generate`，body：

```json
{"user_id": 7, "topic": "反向传播", "student_profile": {"level": "beginner"}, "resource_type": "document"}
```

SSE 关键字段（节选自 `rg-sse.txt`，13 events）：

- HTTP `200`，content-type `text/event-stream; charset=utf-8`
- 事件类型计数：`stage_start×6, stage_end×6, heartbeat×1, done×1`（恰好 1 个 done）
- `done.data` 包含完整 8 字段：
  - `content_blocks`：7 个内容块，每块 `type/heading/content` 齐备
  - `questions`：空数组
  - `response`：`已为您生成「反向传播」的技术速览，共 7 个内容块。`
  - `error`：空字符串
  - `review_status`：`pass`
  - `repair_attempted`：`false`
  - `fallback_used`：`false`
  - `final_status`：`success`
- 内容块人工检查（heading + content）：
  - 「概述」→ "反向传播是训练神经网络的链式法则工程实现：前向传播缓存中间值，反向沿计算图逐层回传梯度..."
  - 「计算图视角：前向与反向」→ 5 个子节，主题一致
  - 「链式法则与局部梯度」、「自动微分如何落地」、「梯度到参数更新」、「常见失效模式与调试」、「核心要点」callout
- 与请求主题一致：标题、正文均围绕"反向传播"展开，资源类型被 Director 路由为 `content`（前端传入 `document` → content 映射）。

## F. 异常、取消与降级 ✅ 通过

### F-1：Workflow 抛异常 → SSE 不为空、恰好一个 done、错误文本正确（Case 3）

- 注入 `resource_workflow.run = AsyncMock(side_effect=RuntimeError("boom"))`
- HTTP `200`，SSE 流内恰好 1 个 `done` 事件
- `done.data == {"error": "资源生成失败，请稍后重试"}`（与约定中文一致）
- producer 抛错时走 `except Exception` 分支，`logger.error(..., exc_info=True)` 触发，控制台可见完整 traceback（验证了 `_run_generation` 内部异常被 ResourceCenter 捕获并转译为 SSE 错误事件）

### F-2：取消消费时后台 producer 兜底

- 由离线测试 `TestResourceCenterStreamGenerate` 覆盖：
  - `test_stream_generate_calls_workflow_run_once`：断言 `assert_awaited_once()`，意味着 producer 与 consumer 协同无残留
  - `test_stream_generate_workflow_exception_yields_error_done`：异常时仍 yield 恰好一个 done
- ResourceCenter `stream_generate` 的 `try/finally` 块确保：consumer 取消时 `producer_task.cancel()` + `await producer_task` 兜底回收（`app/centers/resource_center.py:159-165`）
- 同进程 ASGI harness 中取消场景测试因 ASGITransport 的事件循环边界问题不便直接断言，留作离线测试保障

### F-3：质量门控 / 修复失败

- 不在本轮自动化范围；rg-sse.txt 历史快照显示 `review_status=pass`、`repair_attempted=false`、`fallback_used=false`、`final_status=success`，证明正常路径下门控通过
- Workflow fallback 路径异常处理已存在于 `app/workflows/resource_gen.py:430-435 / 437-474`，但真实跑 fallback 路径需故障注入，未在本轮执行（标"未执行"）

### F-4：未将异常伪装成空 `content_blocks` 的成功交付

- Case 3 验证：异常时 done.data 是 `{"error": "..."}`，而非空 content_blocks（`assert data == {"error": ...}` 通过）
