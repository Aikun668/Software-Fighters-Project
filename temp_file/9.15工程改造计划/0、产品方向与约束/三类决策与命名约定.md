# 三类决策与命名约定

> **定位**：本文件是 `AI_SERVICE_ARCHITECTURE_GUIDE.md` **P3（收敛路由和状态机规则）** 的落地物，
> 与 `产品主线与业务编排约束.md` 配套。前者管「业务域该怎么收」，本文件管「**谁负责路由、谁负责编排、谁负责执行、谁负责状态**」。
>
> **约束力**：新增任何"决定下一步执行什么"的逻辑之前，必须先在本文件登记。
> 违反本文件的改动会被 `tests/test_routing_ownership_contract.py` 直接拦下。

---

## 1. 三类决策（当前共五处实现）

**核心原则**（GUIDE `:48`）：请求级分发、业务内编排、专项执行选择**粒度不同，不得合并成万能路由器**。
要收敛的是**规则的所有权与命名**，不是把判断塞进同一个文件。

| # | 决策类型 | 回答什么问题 | 唯一拥有者 | 唯一调用点 | 输入 | 输出 |
|---|---|---|---|---|---|---|
| 1 | **一级请求级分发** | 这条输入是否**明确要求**专项产物/工作流？ | `app/services/capability_gate.py`（`CapabilityGate`） | `ChatCenter.route` | 用户原始输入 | `CapabilityKind`（默认 `NORMAL_CHAT`） |
| 2 | **二级请求级分发** | 进入专项能力后，**进哪个业务域**？ | `app/centers/router_agent.py`（`RouterAgent`） | `ChatCenter.route` | 用户消息 + `mode` | `ExecutionPlan` |
| 3 | **意图关键词表** | 各类意图由哪些关键词触发？ | `app/services/intent_extractor.py`（`INTENT_REGISTRY`） | 被 #2 借用 | 关键词字符串 | 10 类 `IntentDef` |
| 4 | **内容领域分类** | 这段内容属于 AI 领域还是通用领域？ | `app/services/domain_classifier.py`（`DomainClassifier`，原 `DomainRouter`） | `TutorAgent._respond_node` | `query` / `course_id` / `kb_top_score` | `"ai"` / `"general"` |
| 5 | **专项执行选择** | 资源生成该用哪个专项 Agent？ | `app/orchestration/resource_selector.py`（`ResourceAgentSelector`，原 `Director`） | `ResourceGenWorkflow._plan_node` | `topic` / `resource_type` / `student_profile` | `RouteDecision` |

### 各自的禁止事项（红线）

| # | 禁止 |
|---|---|
| 1 | ❌ 选择 Center 或 Agent；❌ 决定"进哪个业务域"（属 #2） |
| 2 | ❌ 决定"是否进入专项能力"（属 #1）；❌ 选择资源 Agent（属 #5）；❌ 另建一张意图关键词表（表在 #3） |
| 3 | ❌ 在此选择 Center；❌ 决定一级路径（属 #1） |
| 4 | ❌ **参与 Center / Agent 选择**（分类 ≠ 路由）；❌ 越出 `TutorAgent` 使用 |
| 5 | ❌ 被 Center 层或 API 层 import（不得升格为全局请求路由器） |

> ⚠️ **`_QMARKS` 与 `tutor_question.keywords` 的重复是「有意」的**
> （`app/centers/router_agent.py` 模块 docstring 已标注）：两者关键词集合不同，
> 合并会**改变路由行为**。P3 决定：只登记，不合并。

## 2. 分层调用规则

允许的调用方向（`→` 表示"可以调用"）：

```text
internal_api/（API 层：只做协议）
  → Center                                   （唯一业务入口）
      → CapabilityGate                        （一级：是否进专项）
      → RouterAgent                           （二级：进哪个域；仅 ChatCenter）
      → ResultAgent                           （跨域调度 + SSE 终态；⚠️ 待收敛，见 §4）
      → Workflow                              （多阶段业务）
          → ResourceAgentSelector            （专项 Agent 选择；仅 ResourceGenWorkflow；原 Director）
          → Agent                             （单一智能职责）
              → DomainClassifier              （内容分类；仅 TutorAgent；原 DomainRouter）
```

**禁止的调用**（由契约测试机器拦截）：

| 禁止 | 守护断言 |
|---|---|
| API 层**引用** `RouterAgent` / `ResultAgent` / `CapabilityGate` / `Director` / `DomainRouter` | `RO-A06` |
| API 层 **import** 5 处决策模块 | `RO-A05` |
| `app/centers/**` import `ResourceAgentSelector`（原 `Director`） | `RO-A07` |
| 决策模块出现**新的引用者** | `RO-A01..A04` |

## 5. 状态范围约定（GUIDE P3 #4）

| 层级 | 允许持有 | 禁止持有 |
|---|---|---|
| **Workflow** | 跨业务阶段的状态（目标 → 拆解 → 排期） | 成为简单任务/普通问答的默认容器 |
| **Agent** | 仅服务其**本次局部执行**的状态 | 跨业务阶段的状态；跨请求的共享状态 |
| **Center** | 业务入口的编排与统一结果 | HTTP / SSE 传输细节 |

已知偏离（登记，P3-B 处置）：

| # | 项 | 位置 | 问题 | 状态 |
|---|---|---|---|---|
| 1 | ~~双层 LangGraph~~ | `ProfileWorkflow`（5 节点）包 `ProfileAgent`（5 节点） | 外层图与内层**节点集不一致**，内层 `semantic_judge` / `audit` 在生产路径**从不执行** | ✅ **P3-B3b 已合并为单层**：外层 3 节点，`pipeline` 委托 `ProfileAgent.run()`（唯一管线），两个质量节点**已激活**；契约 `PS-A01..A07` 锁定 |
| 2 | 穿透私有节点 | ~~`LearningPathWorkflow._draft_node` / `_revise_node` 直调 `PathAgent._draft_node` / `_revise_node`~~ | 绕过对方 `run()`，绕过其状态约定 | ✅ P3-B3a 已修：被复用节点提为公开 API（`PathAgent.draft/revise`、`ProfileAgent.extract/merge/respond`），契约 `ST-B01/B02` 锁定 |
| 3 | 每请求回调挂实例 | ~~`BaseAgent.run` 把 `_on_token` 存到 `self._current_on_token`~~ | 单请求状态挂在长生命周期实例上 → **并发串流（已复现）** | ✅ P3-B3a 已修：改模块级 `ContextVar` `current_on_token`，契约 `ST-A01..A05` 锁定 |

> **约定补充（P3-B3a 起）**：Workflow 需要复用 Agent 的某个节点时，**必须走公开节点 API**；
> 跨类调用下划线开头的方法视为违规（由 `ST-B02` 拦截）。
> Agent 内的逐请求状态**一律不得挂实例属性**，用 `contextvars` 或参数传递（由 `ST-A01` 拦截）。

## 6. Code Review 检查项（GUIDE P3 #5）

新增或修改代码时，逐条回答：

```text
1. 这段逻辑是否理解 HTTP / SSE 格式？        → 是：只能放 internal_api/ 协议层
2. 它是否决定"一句话该走聊天/计划/资源/…"?    → 是：必须落在 #1 或 #2 的唯一所有者里，并登记
3. 它是否是某业务域内部的多阶段流程？          → 是：该域的 Workflow
4. 它是否只服务一个局部智能职责？              → 是：Agent
5. 它是否被多处复用、且不决定完整业务流程？    → 是：Service
```

**硬性检查**：

- [ ] 是否**新增了第二个**请求级分发点？（`RO-A01..A04` 会红）
- [ ] API 层是否**引用**了路由决策符号？（`RO-A05/A06` 会红）
- [ ] 是否在 `DomainClassifier` 里做了 Center/Agent 选择？（分类 ≠ 路由）
- [ ] 是否把 `ResourceAgentSelector` 的作用域扩大到了资源流之外？（`RO-A07` 会红）
- [ ] 新增长期存在的跨阶段状态前，是否确认它属于 Workflow 而非 Agent？
- [ ] 新增"决定下一步做什么"的逻辑，是否已在本文件 §1 登记？
