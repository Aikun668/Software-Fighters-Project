## 一、这次要解决什么

P0 不新增学习功能，只解决三件事：

1. **P0-B**：让"设置 mock 环境"这一个开关，**从装配层到 provider 层全链生效**；未设置且无 Key 时，返回**统一、可定位的配置错误**，而不是构造期散落异常。
2. **P0-A**：产出**以学生动作为单位**的真实链路台账（四项动作 × 五列 × 三种证据状态），替掉"凭接口名推断已实现"。
3. **P0-C**：把三条最小路径提升到**真链路口径**，并让证据分级落地（离线 / 本地联调 / 真实 HTTP / 人工）。

## 五、技术方案

### 5.1 P0-B：模型配置一致性

**Step 1 · 开关归一（决策 2）**

```python
# app/services/llm_service.py
def _env_mock_flag() -> bool:
    """统一 mock 开关（单一真源）。

    AI_SERVICE_MOCK_LLM 为主；USE_MOCK_LLM 为过渡期兼容别名（任一为真即为真）。
    """
    for name in ("AI_SERVICE_MOCK_LLM", "USE_MOCK_LLM"):
        if os.getenv(name, "").strip().lower() in {"1", "true", "yes", "on"}:
            return True
    return False
```

> `internal_api._get_mock_flag()` 改为调用它（保持 `internal_api` 命名空间下的可 patch 性）。

**Step 2 · `create_llm` / `OpenAILLM` 兜底（决策 1 乙/丙）**

```python
def create_llm(..., use_mock: bool | None = None, ...):
    if use_mock is None:
        use_mock = _env_mock_flag()      # 未显式传 → 跟随环境
```

- 显式传 `True/False` 的**全部现有调用点行为不变**（`None` 是新增默认，原默认 `False` 的调用点里，只有"未传且在无 Key 环境"的会改变行为——正是我们要修的）。
- `OpenAILLM.__init__` 同步支持 `use_mock: bool | None = None`。
- **风险控制**：验收时用"开关三态矩阵"（未设 / `=1` / 显式 `False`）逐态断言。

**Step 3 · 装配层显式透传（决策 1 甲）**

- `ChatCenter.__init__(..., use_mock_llm: bool = False)`；`_get_dispatcher()` 把旗标传给 8 个 Agent + 5 个 Center；
- 4 个 Center 加形参并向惰性默认构造转发；
- `AdjustmentAgent` / `DiagnoseAgent` 补形参（**注意 `DiagnoseAgent:60` 的 `ExerciseAgent()`**）；
- `internal_api._get_chat_center()` → `ChatCenter(use_mock_llm=_get_mock_flag())`。

**Step 4 · 摘要路径**

- `conversation_compress.llm_summarize/self_compress` 加 `use_mock` 形参，调用方 `internal_api/chat.py` 传 `_get_mock_flag()`；即便走 Step 2 兜底，也**显式传**以保证可测。

**Step 5 · fallback 登记**

- `llm_service.py:666/795` 经 Step 2 后自动跟随环境；确认 mock 模式下**不可达**，在验收记录登记为"有意保留"。
