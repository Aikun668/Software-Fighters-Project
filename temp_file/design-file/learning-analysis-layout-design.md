## 一、设计目标

「学情分析」不是普通数据看板，也不是画像聊天页，而是整个学习系统的**解释与决策中心**。

页面需要依次回答五个问题：

1. 我现在学得怎么样？
2. 系统认为我是怎样的学生？
3. 系统为什么得出这些判断？
4. 我的学习状态最近发生了什么变化？
5. 我下一步最应该做什么？

核心信息链路：

```text
对话记录 ────────┐
练习结果 ────────┤
知识掌握度 ──────┼──→ 学情汇总 ──→ 六维画像 ──→ 诊断与依据 ──→ 下一步行动
计划完成情况 ────┤
资源使用记录 ────┘
```

### 1.1 页面承担的功能

- 汇总学习投入、学习成果和近期变化
- 展示 ProfileAgent 持续提取的六维学习画像
- 解释每项画像与诊断的判断依据
- 标记优势、薄弱点、风险和正在进步的方向
- 将分析结果转化为可执行的学习建议
- 为知识图谱、学习计划、练习中心和对话辅导提供跳转入口

### 1.2 页面不承担的功能

- 不提供画像构建对话或任何聊天输入框
- 不直接编辑学习计划
- 不在本页完成练习
- 不重复展示完整知识图谱
- 不允许用户直接修改 AI 推断的能力分数
- 不把所有统计数据无差别堆叠在页面上

## 四、页面头部

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│  学情分析                                                                    │
│  综合你的对话、练习、计划与知识掌握情况，持续更新学习画像                     │
│                                               最近更新：今天 14:32  [刷新]   │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 4.1 元素说明

- 标题固定为「学情分析」
- 副说明强调数据来自多个学习模块，并会持续更新
- 「最近更新」显示画像与统计数据中较新的更新时间
- 「刷新」只重新拉取已有分析数据，不主动调用 LLM 重新分析

### 4.2 刷新交互

```text
点击 [刷新]
    │
    ▼
按钮进入旋转加载态，页面保留旧数据
    │
    ├── 成功 → 更新所有区域 + Toast「学情数据已更新」
    │
    └── 失败 → 保留旧数据 + Toast「更新失败，请稍后重试」
```

页面首次加载使用骨架屏；手动刷新不清空当前内容，避免页面闪烁。

## 五、AI 学情总结

### 5.1 区域结构

```text
┌──────────────────────────────────────────┐
│  AI 学情总结               更新于 14:32  │
│                                          │
│  你是一名目标明确、偏视觉实践型的学习者。│
│  近期深度学习基础提升明显，但线性代数仍是│
│  当前主要阻碍。                          │
│                                          │
│  [查看分析依据]                          │
└──────────────────────────────────────────┘
```

### 5.2 内容规则

总结控制在 3—4 行，必须同时包含：

1. 一个稳定学习特征，如「偏视觉实践型」
2. 一个积极变化，如「Transformer 掌握度提升」
3. 一个当前问题，如「线性代数仍是阻碍」
4. 必要时补充一个节奏或计划风险

禁止使用空泛表达，例如「你学习很努力」「继续加油」。总结必须可以在页面其他区域找到数据依据。

### 5.3 查看分析依据

点击后展开总结下方的依据抽屉，不跳转页面：

```text
┌──────────────────────────────────────────┐
│  本次总结主要依据                         │
│                                          │
│  · 最近 7 天完成 12 个任务                │
│  · Transformer 掌握度从 61% 升至 73%     │
│  · 矩阵运算相关练习正确率仅 48%           │
│  · 4 次主动请求使用图示或代码案例         │
│                                          │
│  数据来源：计划 · 练习 · 图谱 · 对话      │
│                               [收起]      │
└──────────────────────────────────────────┘
```

每条依据标记来源模块，用户点击来源名称可跳转到对应模块的相关位置。

### 6.2 指标定义

| 指标 | 主值 | 辅助值 | 数据来源 | 点击行为 |

数据下降时正常显示向下趋势，不使用鼓励性文案掩盖真实结果。

## 七、我的学习画像

### 7.1 六维画像

画像直接对应源码中的 ProfileAgent 六个维度：

| 页面名称 | Profile 字段 | 展示内容 |
|----------|--------------|----------|
| 知识基础 | `knowledge_base` | 0—100 基础水平与阶段描述 |
| 学习方式 | `cognitive_style` | 视觉、听觉、实践、理论等偏好 |
| 学习目标 | `learning_goal` | 目标内容、清晰度与稳定程度 |
| 薄弱环节 | `weak_points` | 薄弱知识与严重程度 |
| 学习节奏 | `learning_pace` | 学习频率、时段与任务节奏 |
| 兴趣方向 | `interest_direction` | 持续关注的领域及置信度 |

> 页面文案使用「学习方式」，底层字段继续使用 `cognitive_style`，避免前端术语过于学术化。

### 7.2 雷达图交互

- 默认展示六个维度的当前综合分
- 悬停顶点显示：维度名称、得分、简短解释、状态
- 点击顶点后，页面下方「画像详情」切换到对应维度
- 雷达图只读，不允许拖拽修改
- 当某维度未形成稳定判断时，使用虚线顶点并显示「分析中」

### 7.3 画像完整度

```text
画像完整度 83% · 已确认 5/6 维 · 基于 26 次有效学习行为
```

完整度表示系统掌握的信息覆盖程度，不代表学生能力得分。

## 八、当前最值得关注

此区域不是简单的「薄弱点 TOP 3」，而是从所有模块中选择当前最影响学习的三个事项。

### 8.1 诊断类型

| 类型 | 示例 | 优先级依据 |
|------|------|------------|
| 薄弱阻塞 | 线性代数影响多个后续知识点 | 严重度 × 影响范围 |
| 正向变化 | Transformer 掌握度提升 12% | 近期增幅 × 延续价值 |
| 计划风险 | 本周 3 项任务延期 | 延期数量 × 任务优先级 |
| 节奏异常 | 连续 4 天学习时长下降 | 变化幅度 × 持续时间 |
| 画像缺口 | 学习目标仍不明确 | 缺失维度 × 个性化影响 |

### 8.2 单条诊断结构

```text
┌────────────────────────────────────────┐
│  ① 线性代数基础薄弱                    │
│     已连续影响矩阵运算、反向传播等      │
│     3 个知识点                          │
│                                        │
│     [查看知识图谱] [专项练习]           │
└────────────────────────────────────────┘
```

一条诊断最多提供两个操作按钮，避免操作过载。

### 8.3 查看全部诊断

点击后从右侧打开抽屉：

```text
┌──────────────────────────────────────────┐
│  全部学情诊断                      [关闭] │
├──────────────────────────────────────────┤
│  [全部] [需关注] [正在进步] [计划风险]   │
│                                          │
│  高优先级                                │
│  ● 线性代数基础薄弱                      │
│    依据：近 3 次练习正确率 48%           │
│                                          │
│  正在进步                                │
│  ● Transformer 掌握度 +12%              │
│    依据：图谱 mastery 变化               │
│                                          │
│  已观察                                  │
│  ● 晚间学习完成率更高                    │
└──────────────────────────────────────────┘
```

抽屉用于浏览，不在其中增加复杂编辑功能。

| 状态 | 页面显示 | 含义 |
|------|----------|------|
| `confirmed` / `active` | 已确认 ✓ | 多个有效信号支持，当前可用于个性化 |
| `tentative` | 分析中 ? | 已发现线索，但证据不足 |
| `stale` | 待验证 | 历史判断近期没有获得新证据 |
| 无数据 | 尚未形成 | 当前无法做出可靠判断 |

### 9.4 用户纠错入口

用户不能直接修改能力分数，但可以对主观画像进行轻量反馈：

```text
这个判断符合你吗？  [符合] [不太符合]
```

- 「符合」记录正反馈，提高该结论可信度
- 「不太符合」打开简短原因选择，不立即覆盖画像
- 客观结果如练习正确率、知识掌握度不提供纠错按钮

V1 若无反馈接口，可只保留前端状态或暂不实现该入口。

## 十二、为你推荐的下一步

### 12.1 设计原则

- 默认展示三条，分别覆盖「补弱」「巩固」「节奏/计划」

## 十四、数据来源与可信度

### 14.1 数据来源汇总

| 页面区域 | 主要数据来源 |
|----------|--------------|
| AI 学情总结 | 六维画像 + 练习分析 + 图谱变化 + 计划状态 |
| 本周学习概览 | 活动记录 + 计划任务 + 练习记录 + 图谱 |
| 六维学习画像 | ProfileAgent / StudentProfile |
| 当前最值得关注 | 薄弱点 + mastery 变化 + 延期任务 + 行为趋势 |
| 画像判断依据 | 对话提取结果 + 练习行为 + 资源行为 + 计划行为 |
| 学习趋势 | 活动记录 + 练习记录 + mastery 历史 |
| 知识掌握分布 | 知识图谱节点 mastery |
| 下一步推荐 | 当前诊断与各模块可执行内容 |

### 14.2 可信度展示原则

- 明确区分「客观统计」和「AI 推断」
- AI 推断必须展示状态：已确认、分析中、待验证
- 推断必须可以查看依据，禁止只显示结论
- 数据不足时明确显示「尚未形成判断」，不填充虚假结论
- 同一条行为不能被包装为多个独立证据

## 十五、加载、错误与空状态

### 15.1 首次加载

- 页面头部先显示
- 各卡片分别显示与最终布局一致的骨架屏
- 某个区域加载失败不阻塞其他区域
- 超过约定时间后显示局部重试按钮

### 15.2 全新用户

```text
┌────────────────────────────────────────────────────────────────────┐
│                                                                    │
│                      你的学情分析正在形成                           │
│                                                                    │
│       完成一次对话、练习或学习任务后，系统会逐步了解你的            │
│       知识基础、学习方式、目标、节奏和兴趣方向。                    │
│                                                                    │
│               [开始一次对话]    [做一组入门练习]                   │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
```

新用户状态不展示全零雷达图，避免让用户误解为能力为零。

### 15.3 部分画像缺失

- 已有维度正常显示
- 缺失维度显示虚线顶点和「分析中」
- 画像详情说明还缺少哪类有效行为
- 不强迫用户进入画像问答

示例：

```text
学习节奏：尚未形成判断
再完成 3—5 天学习任务后，系统才能识别你的稳定学习节奏。
```

### 15.4 局部错误

```text
┌──────────────────────────────────────┐
│  学习趋势暂时加载失败                │
│  其他学情数据仍可正常查看            │
│                         [重新加载]   │
└──────────────────────────────────────┘
```

## 十六、响应式布局

| 视口宽度 | 页面行为 |
|----------|----------|
| ≥ 1200px | 按设计稿显示双栏与三列卡片 |
| 900px—1199px | 双栏比例收紧，行动卡片保持三列或改两列 |
| 768px—899px | 双栏改为单列，雷达图先于诊断列表 |
| < 768px | 所有区域单列，画像标签横向滚动，抽屉改全屏层 |

比赛演示以桌面端为优先；移动端保证基本可读与可操作，不要求复杂图表在小屏保留全部标签。

## 十七、数据刷新策略

### 17.1 刷新时机

- 首次进入页面时加载
- 从练习中心、学习计划等模块返回本页时检查数据版本
- 用户点击「刷新」时重新拉取
- 页面保持打开时，可每 5 分钟静默检查一次更新时间

### 17.2 不建议的行为

- 不对所有卡片分别高频轮询
- 不在每次进入页面时强制调用 LLM 生成新总结
- 不因单次对话消息立即大幅改写稳定画像
- 不在数据未变化时播放虚假的更新动画
