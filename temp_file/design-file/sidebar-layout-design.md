## 一、侧边栏在系统中的位置

```
┌──────────────────────────────────────────────────────────────┐
│  Header（固定顶部 60px）                                      │
│  Logo + 通知 + 设置 + 用户头像                                 │
├────────┬─────────────────────────────────────────────────────┤
│        │                                                     │
│  THIS  │  Main Content（router-view 动态切换）                 │
│  FILE  │                                                     │
│        │                                                     │
│        │                                                     │
│        │                                                     │
├────────┤                                                     │
│        │                                                     │
└────────┴─────────────────────────────────────────────────────┘
```

**位置规则**：
- 固定于页面左侧，Header 下方
- 顶部对齐 Header 底边（top: 60px）
- 高度撑满剩余视口（bottom: 0）
- z-index 高于内容区，低于弹窗/下拉菜单
- 独立滚动（overflow-y: auto），不随页面内容滚动

## 二、双态切换：展开 ↔ 收起

### 2.1 展开态（默认，240px）

┌────────────────────────────┐

│  │ 对话项 3              │  │
│  │ ...                   │  │
│  └──────────────────────┘  │
├─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─┤
│  🔗 知识图谱               │
│  🗺️ 学习计划               │
│  📁 资源工坊               │
│  ✏️ 练习中心               │

```

### 2.2 收起态（72px）

```
┌──────┐
│  📐  │
├──────┤
│  💬  │
├──────┤
│  ·¹  │
│  ·²  │
│  ·³  │
│  ·⁴  │
├──────┤
│  🔗  │
│  🗺️  │
│  📁  │
│  ✏️  │
│  📊  │
│  🧠  │
├──────┤
│  ▶   │
└──────┘
```

**收起态规则**：
- 所有文字隐藏
- 对话记录缩为小圆点（直径 8px），hover 显示 tooltip 标题
- 功能导航项只显示 emoji 图标（20px 居中）
- 新建对话变为圆形图标按钮
- 新建对话图标右上角显示未读消息数量角标（如有）

### 2.3 切换触发方式

| 触发方式 | 行为 |
|---------|------|
| 点击底部「收起/展开」按钮 | 切换展开/收起 |
| 收起态 hover 功能图标 | 弹出 tooltip 显示完整文字 |
| 收起态点击功能图标 | 直接导航，不自动展开 sidebar |
| 收起态点击对话圆点 | 切换到该对话，不自动展开 sidebar |

> **【待确认 ①】** 点击收起态功能图标时，是否需要 sidebar 自动展开 1 秒再收起？还是保持收起？

### 2.4 过渡动画

| 属性 | 值 |
|------|-----|
| width 过渡 | 300ms cubic-bezier |
| 文字淡入淡出 | 150ms，收起时先隐藏文字再收缩宽度 |
| 图标位移 | 200ms，从左侧偏移到居中 |

## 三、侧边栏项目结构与层级

```
Sidebar
├── 1. Logo 区
├── 2. 新建对话（按钮）
├── 3. 对话记录（折叠组）
│   ├── 3.1 对话项 1
│   ├── 3.2 对话项 2
│   ├── 3.3 对话项 3
│   └── ...（动态列表）
├── 4. 功能导航（静态列表）
│   ├── 4.1 知识图谱
│   ├── 4.2 学习计划
│   ├── 4.3 资源工坊
│   ├── 4.4 练习中心
│   ├── 4.5 数据看板
│   └── 4.6 我的画像
└── 5. 折叠/展开按钮
```

**核心设计决策**：对话记录列表存在于侧边栏内部，而非每个对话页面的子侧边栏。这意味着：
- 用户在任意页面都能看到对话历史
- 点击对话项直接跳转到对应对话页面
- 不再有"外层 sidebar + 内层对话 sidebar"的双层嵌套问题

## 四、各组件详细规格

### 4.1 Logo 区

```
┌──────────────────────────────┐
│                              │  h: 56px（含上下 padding）
│   ┌──────┐                   │
│   │ emoji│  品牌名            │  品牌名: 18px bold
│   │ 图标 │  副标题            │  副标题: 11px regular
│   │36×36 │                   │
│   └──────┘                   │  图标容器: 36×36, r10px
│                              │
└──────────────────────────────┘
```

**行为**：
- 展开态：显示图标 + 品牌名 + 副标题
- 收起态：只显示图标，居中
- 点击：无交互（纯展示）
- 收起态 hover 图标：弹出 tooltip "智学 DeepTutor"

### 4.2 新建对话按钮

```
展开态：
┌──────────────────────────────┐
│        💬  新建对话           │  h: 40px, w: 216px（240 - 24px padding）
└──────────────────────────────┘  r: 12px

收起态：
┌────┐
│ 💬 │  h: 40px, w: 40px, r: 10px（圆形），居中
└────┘
```

**位置**：Logo 区下方，margin-top: 8px，margin-bottom: 4px  
**覆盖 padding**：左右 12px

**行为**：
- 点击：创建新对话 → 自动跳转到对话辅导页面 → 新对话出现在对话记录列表顶部
- 收起态点击：同上，但 sidebar 保持收起

> **【待确认 ②】** 点击「新建对话」后的行为：
> - A：创建空白对话 → 跳转到对话页 → 用户输入第一句话后，对话自动以第一句话的前 N 字命名
> - B：弹出对话框让用户先输入对话标题 → 再创建
> - C：直接创建名为「新对话」的项 → 跳转
> 
> 当前推荐 A，最自然。

### 4.3 对话记录组

#### 4.3.1 组折叠头

```
┌──────────────────────────────┐
│  📋 对话记录 (4)        ▾    │  h: 36px
└──────────────────────────────┘  r: 8px
```

**规格**：
- 左侧：📋 emoji + "对话记录" (11px, uppercase)
- 右侧：数量角标 "(4)" + ▾ 箭头
- 展开时：箭头 ▾ 朝下
- 折叠时：箭头 ▸ 朝右

**行为**：
- 点击折叠头：切换对话列表的显示/隐藏
- 折叠态下保留：折叠头本身 + 当前选中的那一条对话

**折叠后的最小态**（对话列表隐藏，只保留头部 + 当前项）：

```
┌──────────────────────────────┐
│  📋 对话记录 (4)        ▸    │
│  ┌──────────────────────┐    │
│  │ 💬 深度学习基础       │    │  ← 只保留 active 项
│  │    卷积层、池化层...  │    │
│  └──────────────────────┘    │
└──────────────────────────────┘
```

> **【待确认 ③】** 对话记录折叠/展开状态是否需要持久化（localStorage）？

#### 4.3.2 单个对话项

**默认态**：

| 预览文字 | 12px regular | 1 行截断（ellipsis），最多 22 字 |
| 时间 | 11px regular | 右下角，"刚刚"/"5分钟前"/"1小时前"/"昨天"/日期 |

**交互三态**：

```

#### 4.3.3 对话列表滚动

- 对话记录区域设置了最大高度？
  - **当前方案**：对话列表区域自动撑开，功能导航区域挤到底部
- 如果对话过多（50+），功能导航项会被挤出视野
  - **推荐方案**：对话列表区域设 max-height，剩余空间留给功能导航 + 折叠按钮
  - 滚动条：hover 时显示细滚动条（4px），默认隐藏
  - 对话列表撑满时不自动折叠功能导航

> **【待确认 ⑤】** 对话过多时，对话区域和功能导航之间的空间分配策略：
> - A：对话区域设 max-height（如 400px 约 7-8 条对话），超出滚动，功能导航始终可见
> - B：对话区域无限扩展，功能导航挤到底部，可滚动看到
> - C：对话区域占固定比例（60%），功能导航占底部 40%
>
> **推荐 A**，保证功能导航始终可访问

## 五、动态交互流程

### 5.1 对话创建全流程

```
用户点击 [新建对话]
       │
       ▼
  ┌─────────────────┐
  │ 调用后端 API     │  POST /api/conversations
  │ 创建新对话       │  body: { title: null }
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ 对话列表顶部插入  │  标题显示 "新对话"
  │ 新项（临时状态）  │  active = true
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ 路由跳转到        │  router.push('/question-nav-chat')
  │ 对话辅导页面      │  query: { conversationId: xxx }
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ 用户输入第一句话  │
  │ 并发送            │
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ 对话标题自动更新  │  取用户第一条消息的前 20 字
  │ "卷积层的工作..." │  列表项标题实时更新
  └─────────────────┘
```

### 5.2 对话切换流程

```
用户在 sidebar 点击对话项
       │
       ▼
  ┌─────────────────┐
  │ 当前对话项变为    │  active = true
  │ 选中态（高亮）    │  其他项恢复默认态
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ 路由跳转到        │  router.push(`/question-nav-chat?conversationId=xxx`)
  │ 对话辅导页面      │
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ 对话页加载历史    │  从后端拉取消息列表
  │ 消息              │  滚动到最新消息
  └─────────────────┘
```

> **【待确认 ⑧】** 切换对话时，之前对话的输入框草稿是否需要保留？
> - A：不保留，切换即清空输入框
> - B：每个对话独立保留草稿（localStorage）
> - C：只有当前对话保留草稿
>
> **推荐 B**，就像微信每个聊天独立保留草稿

### 5.3 对话删除流程

```
用户 hover 对话项 → 出现 [⋮] → 点击 🗑️删除
       │
       ▼
  ┌─────────────────┐
  │ 弹出确认对话框    │  "确定要删除「深度学习基础」对话吗？此操作不可撤销。"
  │ [取消] [确认删除] │
  └────────┬────────┘
           │ 点击确认
           ▼
  ┌─────────────────┐
  │ 调用删除 API     │  DELETE /api/conversations/{id}
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ 从对话列表移除    │  动画：向左滑出 + 淡出 200ms
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ 如果删除的是      │  是 → 自动选中列表第一项 → 跳转
  │ 当前选中项？      │  否 → 保持当前选中
  └─────────────────┘
```

### 5.4 对话重命名流程

```
用户 hover 对话项 → 出现 [⋮] → 点击 ✏️重命名
       │
       ▼
  ┌─────────────────┐
  │ 标题变为可编辑    │  inline editing
  │ input 框          │  自动 focus + 全选文字
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ 回车 / 失焦      │
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ 调用更新 API     │  PATCH /api/conversations/{id}
  │                  │  body: { title: "新标题" }
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ 列表项标题更新    │  直接替换文字
  └─────────────────┘
```

### 5.5 实时更新流程（对话列表动态变化）

```
场景 1：对话页 AI 回复完成
  → SSE stream 结束 → 更新当前对话的 preview 字段（取最后一条消息）
  → sidebar 对话列表的预览文字实时刷新

场景 2：新对话创建
  → 列表顶部插入 → 滚动到顶部
  → 如果有「新建对话」的临时项，先移除再插入正式项

场景 3：对话时间更新
  → 每 30 秒刷新所有对话的"X 分钟前"时间显示
  → 使用 setInterval 统一更新
```

| 视口宽度 | Sidebar 行为 |
|---------|-------------|
| ≥ 1024px | 正常显示，可展开/收起 |
| 768px - 1023px | 默认收起（72px），点击展开按钮可展开 |
| < 768px | 默认隐藏，通过汉堡菜单按钮打开 overlay 模式 |

**Overlay 模式（移动端）**：
- Sidebar 作为 overlay 覆盖在内容区上面
- 背景加上半透明遮罩（backdrop）
- 点击遮罩或导航项后自动关闭
- 宽度：280px（移动端手指操作需要更大点击区域）

> **【待确认 ⑨】** 移动端 overlay 模式是否需要？还是直接不做移动端适配？
> 如果比赛只展示桌面端，可以暂时不实现移动端。
