# Relay 核心协议（尽量保持在 1 页）

1. 单一真相：Git 工作树和可复现测试优先，状态文档次之，口头历史最低。
2. 总督只做项目扫描、分包、取舍、验收、更新持久记忆；不碰业务代码。Worker 只实现领到的一个任务包，不越界。
3. 每个任务目标应在一次 Worker 窗口内完成可验收闭环，预计峰值常规 35–70K；大于约 80K 先拆，小于 20K 且同模块同验证链路则优先合并。
4. Worker 只阅读任务包指定入口与必需依赖，先 `git status --short` 检查已有改动。禁止无目标全仓库搜索、打印整个文件、粘贴巨大日志。
5. 上下文 ≥80K 不新增子目标；≥90K 停止新实现，报告后退出；已跨 100K 不超过 3 次必要交接轮次。提示词无法自动阻止 API 越界。
6. Worker 写 `relay/reports/Txxx.md`：实际改动、执行过的验证、结果、未完成、风险、下一步。若遇到任务外范围或不确定接口，报告阻塞，不擅自扩项。
7. 总督验收先比任务验收条件、diff 和测试证据，不盲信“完成”；更新 `QUEUE` 与 `DECISIONS`，必要时补开任务。
8. 总督接近 60–70K 上下文或验收 5–8 包退休，必须更新 `GOVERNOR_WILL.md`。下一任以落盘文件与实际代码为准。
9. v1 仅允许一个 Worker 修改同一 Git 工作树；如并发必须隔离 worktree。不得重置/覆盖用户未提交改动，不得隐式提交/推送。
10. 禁止在状态/报告文件写入密钥、令牌、隐私信息；只保留有助恢复工作的最短事实。
