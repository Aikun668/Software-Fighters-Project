## 二、接线点选择与理由

**接线点：`chat_task_dispatcher.py` 的 `execute()` 中下发 finalize CONTENT 事件的 else 分支**（原 336–342 行处）。

```
payload = self._serialize_final_payload(result, progress)
ui_blocks = extract_ui_blocks_from_payload(payload)   # 清理正文
yield _finalize_event(payload, streamed=emitted_tokens)  # 清理后正文走原路
for block in ui_blocks:
    yield visualization_event(block)                  # 独立 SSE 事件，正文之后
```

选择理由：
1. `execute()` 是**所有 center 最终正文的唯一下发点**（tutor = auto 模式的最终正文就在 finalize CONTENT 帧的 `payload.response/content` 里），一处接线覆盖全模式；
2. 调查确认（证据：`app/centers/chat_center.py` 762–869 行）：`ChatCenter.stream_chat` 的 `_producer` 对非 TOKEN/CONTENT/ERROR/DONE 事件**原样透传**（`await queue.put(event)`），VISUALIZATION 事件自动进 SSE 流——**无需碰任何脏文件**；
3. 备选否决：`chat_presentation.py` 是纯函数层、无 yield 事件能力；`ensure_user_visible_response` 被两处共享，不适合夹带副作用；脏文件（tutor_agent / llm_service / response_sanity / main 等）从一开始就不在考虑范围。
4. 事件顺序：`center_start → token… → center_end → content(清理后正文) → visualization* → … → done`。visualization 紧跟本任务正文之后、最终 done 之前，符合"正文之后"的要求；`_serialize_result`（done 载荷 results[]）未动，sse_contract 基线不受影响。

`visualization_event(block)` 对已规范化的 block 二次校验必过（parse 幂等，实测接线用例通过），不会抛 ValueError 打断事件流。

## 四、已知限制（如实报告）

1. **流式期间围栏短暂可见（任务单已预期）**：tutor 走 `chat_stream` 逐字吐 token，围栏原文会先流到前端；接线只在最终 CONTENT 帧剥离。这是 MVP 已知限制。
2. **结构性问题（重点）**：auto 模式发过 token 后，最终 CONTENT 帧带 `partial=True`，**前端会跳过该帧的文本追加**（防重复渲染合同，见 `_finalize_event` docstring 与既有测试 `test_streaming_center_final_frame_keeps_partial`）。因此前端**不会用清理后的最终正文替换已渲染的 token 文本**——token 流里的围栏会在前端界面**持续残留**，除非前端自行处理（如在渲染层隐藏围栏、或消费 visualization 事件时做替换）。后端在不破坏既有 partial 合同的前提下无法单方面解决，需要前端配合（前端属同事地盘，本任务不碰）。
3. **assistant_content 对账含围栏**：`ChatCenter.stream_chat` 把 token 流全文（含围栏 JSON）累加进 `assistant_content` 并用于知识节点抽取（截取前 2000 字符），围栏文本可能进入抽取输入。影响轻微；修复需改 `chat_center.py`，超出本任务允许清单，未动。
4. **围栏识别约束**：只认 3-backtick、`ui-block` 严格小写、围栏行首无缩进。4+ backtick / 缩进围栏 / `UI-BLOCK` 均不识别（当普通文本保留，不会误剥离，但也抽不出 block）。
5. 非法围栏保留在正文的代价：前端会看到一段 JSON 代码块（失败不吞正文的取舍）。
6. 多任务场景每个任务的 finalize 正文都会过抽取，visualization 事件在各任务 content 之后、下一任务/最终 done 之前发出。
