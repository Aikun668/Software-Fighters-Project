## 目标（只写可验收结果）
实现一个纯前端的 UI block 校验与分发模块：
- 输入任意未知 JSON，按 `{type, version, props}` 结构做严格校验；
- 只有 type 与 version 都注册过、props 通过该类型的 schema 时，才返回可渲染的结果，否则返回带原因的错误；
- 注册表把 `type: "attention_matrix"` 映射到 `AttentionMatrix.vue`。

本任务**不**把 registry 接入 `ChatThread.vue` 或任何 view，也不改后端。接入与后端 `visualization` 事件属于后续任务，等协议定下来再做。

## 已知事实 / 代码入口
- 协议来源：`docs/聊天界面优化/reference/tutor_attention_implementation.md` 第 52–61 行。block 形如 `{"type": "attention_matrix", "version": 1, "props": {"tokenCount": 5, "mode": "causal"}}`。
- 组件：`frontend/src/components/chat/AttentionMatrix.vue`，Props 为 `tokenCount`、`mode`、可选 `queryLabels`、`keyLabels`、`weights`。
- 决策约束（必须遵守）：
  - **D-004**：LLM 不直接输出 HTML/Vue，只输出结构化 block，前端做 schema 校验。
  - **D-003 / D-007**：AI 输出的 block **不得包含 `weights`**，否则会把非真实权重当成热力图展示。schema 必须显式拒绝 `weights` 键。
  - `tokenCount` 限定为整数 3..8。`mode` 只能是 `causal` 或 `bidirectional`。`queryLabels` / `keyLabels` 若提供，必须是字符串数组，长度等于 `tokenCount`。
- 依赖约束：不新增依赖（不引入 zod 等库），校验用手写 TypeScript 类型守卫。
