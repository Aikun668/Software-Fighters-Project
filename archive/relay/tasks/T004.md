## 目标（只写可验收结果）
前端聊天能接收并渲染后端发出的 `visualization` SSE 事件：

1. `src/api/chat.ts`（干净文件）：`parseSSEStream` 新增 `visualization` 事件分支（payload 形状：`{type: 'visualization', data: {type, version, props}}`）。事件经 `dispatchUiBlock`（`frontend/src/components/chat/ui-blocks/registry.ts`）校验：
   - 合法 → 把 `{component, props}` 交给上层（回调或消息装配方式由你按现有代码风格定，参照既有 onProgress 等模式）；
   - 非法 → 交给上层一个可显示的轻量降级提示（如"图表数据不合法，已隐藏"），**绝不能影响正文**，也绝不能抛异常。
2. `src/utils/markdown.ts`（干净文件，D-001 渲染唯一入口）：渲染前剥离**合法**的 ` ```ui-block ` 围栏——只剥离"JSON 可解析且通过 `ui-blocks/schema.ts` 校验"的围栏（schema 是纯函数，可直接 import，不引 Vue）；**非法围栏原样保留**（与后端"失败不吞正文"合同一致）。用途：后端只在最终正文剥离围栏，token 流式期间及 partial 帧被跳过时正文会有围栏残留（T006 已确认的结构性问题），渲染层剥离一劳永逸。
3. `frontend/src/components/chat/ChatThread.vue`（**他人有未提交改动的脏文件**）：以**纯新增**方式接入渲染——把收到的合法 block 渲染到对应助手消息下方（动态组件 + props），非法的渲染小灰字提示。
   - **死规矩**：开工前先 `git diff -- frontend/src/components/chat/ChatThread.vue` 把现有 diff 看清并当作只读基线；你的改动只许新增行/新增块，不删除、不修改任何现有行（确需在已有函数加参数时，保持原行为完全不变）；收尾再跑一次该 diff，确认你开工前看到的他人改动**一行不少**全在。
4. 测试：
   - 扩展 `src/api/__tests__/chat.spec.ts`：visualization 事件合法→回调收到组件与 props；非法→降级路径、正文回调不受影响。
   - 扩展 markdown 相关 spec（`src/utils/__tests__/`）：合法围栏被剥离、非法围栏保留、无围栏原样、普通代码块不受影响。
   - ChatThread 层用例：若已有 ChatThread spec 则扩展；若无，新建最小 spec 覆盖"合法 block 渲染出组件、非法 block 降级提示、正文不受影响"三场景（渲染深度不必过分追求，能断言关键 DOM/组件存在即可）。
