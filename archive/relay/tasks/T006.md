## 目标（只写可验收结果）
让 tutor 聊天的 SSE 流具备"发图表"的完整机关（MVP 管线）：

1. 新增 `ai-service/app/services/visualization_blocks.py`：纯函数
   `extract_ui_blocks(text: str) -> tuple[str, list[dict]]`
   - 识别正文中的 ` ```ui-block ` 围栏（fenced code，info string 为 `ui-block`，内容是一个 JSON 对象）；
   - JSON 解析后用 `app.events.visualization.parse_ui_block` 校验：**合法**的收集进列表、围栏从返回文本中剥离；**非法**的围栏原样保留在文本里（失败不吞正文）；
   - 无围栏时返回原文与空列表；多个围栏全部处理。
2. 接线：通读 `app/centers/chat_task_dispatcher.py` 与 `app/centers/chat_presentation.py`（两者都是干净已提交文件），找到"tutor 最终正文下发"的最小接线点，把抽取接上：最终正文先过 `extract_ui_blocks`，清理后的文本走原路下发，随后对每个合法 block 调 `visualization_event(block)` 作为独立 SSE 事件（正文之后）发出。
   - **接线点只允许落在干净文件**（chat_task_dispatcher.py / chat_presentation.py / app/events/ 下 / 新文件）。
   - 若调查后确认绕不开脏文件（`tutor_agent.py`、`llm_service.py`、`response_sanity.py`、`routing_audit.py`、`main.py`、`prompts/tutor_agent/system.yaml`、`.env.example`，这些全是他人未提交改动）→ **停止实现，BLOCKED**：报告候选接线点、为何绕不开、最小侵入建议。
   - 注意流式：token 流期间围栏可能短暂可见，最终正文被替换后消失——这是已知 MVP 限制，写进报告即可，不要求解决；但若你发现"最终正文帧在 token 已流出后会被前端跳过"之类导致围栏残留的结构性问题，如实写进报告。
3. 测试：新增 `ai-service/tests/test_visualization_blocks.py`（pytest），至少覆盖：无围栏原样返回；合法围栏抽取并剥离；多个围栏；JSON 非法的围栏保留；含 `weights` 的围栏保留（D-007 校验拒绝）；非围栏的普通代码块不受影响。若接线点可在单测中触达，补最小接线测试（合法 block → 产生 visualization 事件、非法 → 正文不受影响）。

本任务**不改提示词**（提示词让 LLM 学会输出 ui-block 围栏，属同事地盘，另立任务）；**不碰前端**。
