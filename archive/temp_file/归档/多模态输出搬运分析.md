# 多模态输出搬运分析：DeepTutor + OpenMAIC → 我们的系统

## 两个参考项目的定位差异

| 维度 | DeepTutor | OpenMAIC | 我们 |
|------|-----------|----------|------|
| 核心能力 | 数学/科学可视化解释 | 课程大纲→多媒体课件生成 | AI 答疑+学习资源生成 |
| 多模态重点 | 图解说明、数学动画 | 图片/视频/TTS/幻灯片 | **两者都要**：答疑图解 + 学习资源 |
| 架构语言 | Python (LangGraph) | TypeScript (Next.js) | Python (LangGraph) |
| 质量策略 | 3 阶段 LLM 流水线保质量 | Prompt 约束 + 检查清单 | 借鉴 3 阶段 |

## 一、从 DeepTutor 搬什么

### 1. 三阶段可视化流水线（必搬⭐⭐⭐）

DeepTutor 的核心设计：不是让 LLM 一次性输出图表代码，而是拆成 3 步：

```
学生问题 → Analysis Agent → Code Generator → Review Agent → 最终图表
            (分析该画什么)   (生成代码)      (审查修正)
```

**为什么必须 3 阶段？**
- Analysis Agent 先判断「这个问题适合画图吗？画什么类型？」——避免不必要时生成
- Code Generator 专注代码生成，不被「要不要画」分心
- Review Agent 做质量把关——检查代码是否正确、美观、可渲染

**我们怎么搬：**
```python
# app/agents/visualize/visualize_pipeline.py (新建)
class VisualizePipeline:
    async def run(self, question: str, answer: str) -> VisualizeResult:
        # Stage 1: 分析该生成什么
        analysis = await self._analyze(question, answer)
        if not analysis.should_visualize:
            return VisualizeResult.skip()

        # Stage 2: 生成可视化代码
        code = await self._generate_code(analysis)

        # Stage 3: 审查修正
        reviewed = await self._review(code, analysis)
        return VisualizeResult(render_type=analysis.render_type, code=reviewed.code)
```

### 2. 静态优先路由（必搬⭐⭐⭐）

DeepTutor 的渲染类型优先级：**SVG > ChartJS > Mermaid > HTML > Manim**

原则：能用静态 SVG 解决的不上 JS 图表，能用 Mermaid 的不上 HTML，能用 HTML 交互的不上视频。

```python
# render_type 优先级
RENDER_PRIORITY = {
    "svg": 1,       # 最快，纯矢量，直接嵌入
    "mermaid": 2,   # 快，适合流程图/时序图/类图
    "chartjs": 3,   # 中等，适合数据可视化
    "html": 4,      # 慢但交互性强
}
```

**对我们意味着什么：** 答疑场景优先 Mermaid（Markdown 原生支持），PPT/资源场景优先 SVG。

### 3. Mermaid 作为 Markdown 一等公民（必搬⭐⭐⭐）

DeepTutor 的 solve pipeline 中，LLM 可以直接在 Markdown 答案中嵌入 Mermaid 代码块：

```markdown
老师给你画个流程图：

​```mermaid
graph TD
    A[牛顿第一定律] --> B[惯性]
    A --> C[力是改变运动状态的原因]
    B --> D[质量越大惯性越大]
​```
```

这是**实现成本最低、体验提升最大**的功能。我们已经在做 SSE streaming Markdown，加上 Mermaid 渲染就是水到渠成。

**需要做：** 前端 Markdown 渲染器支持 Mermaid（react-mermaid / mermaid.js）

### 4. MathAnimator 流水线（暂不搬❌）

DeepTutor 的 Manim 视频生成是 5 阶段流水线+4 次重试循环，依赖 subprocess 调用 Manim 渲染引擎。对 34 天来说太复杂，且需要 GPU 服务器安装 Manim 依赖。**改用 PPT+TTS 方案替代（见下文 OpenMAIC 部分）。**

## 二、从 OpenMAIC 搬什么

### 1. 提供者适配器模式（必搬⭐⭐⭐）

OpenMAIC 的 provider registry + adapter 模式非常干净：

```
IMAGE_PROVIDERS = {
    "openai": OpenAIImageConfig(...),
    "seedream": SeedreamImageConfig(...),
}

def generate_image(config, options):
    provider = IMAGE_PROVIDERS[config.provider_id]
    return provider.adapter.generate(api_key, options)
```

**我们怎么用：** 不需要 7 个图像提供者 + 7 个视频提供者。我们只需要：

```python
# app/services/media/__init__.py
MEDIA_ADAPTERS = {
    "openai_image": OpenAIImageAdapter(),   # DALL-E
    "openai_tts": OpenAITTSAdapter(),       # TTS for video voiceover
}
```

适配器接口：
```python
class ImageAdapter(Protocol):
    async def generate(self, prompt: str, size: str) -> ImageResult: ...
    async def test_connectivity(self) -> bool: ...
```

### 2. MediaGenerationRequest 桥接模式（必搬⭐⭐）

OpenMAIC 的关键洞察：**LLM 决定生成什么，适配器决定怎么生成。**

```python
@dataclass
class MediaGenerationRequest:
    type: Literal["image", "diagram", "video"]
    prompt: str          # LLM 写的生成 prompt
    element_id: str      # 全局唯一 ID，如 "gen_img_1"
    priority: int = 5    # 1-10，低优先级可以后生成
```

LLM 在回答中输出：
```json
{
  "answer": "牛顿第二定律是 F=ma...",
  "media_requests": [
    {"type": "diagram", "prompt": "牛顿第二定律受力分析图...", "element_id": "gen_1"}
  ]
}
```

后端解析 `media_requests`，异步生成图表，SSE 推送完成事件给前端替换占位符。

### 3. LLM Prompt 约束模式（必搬⭐⭐⭐）

OpenMAIC 的 `image-instructions.md` / `video-instructions.md` 的核心策略：

- **明确告诉 LLM 什么时候该用图**："优先使用已有资源；只在概念需要可视化时才生成"
- **全局唯一 ID**：`gen_img_1`, `gen_img_2`... 跨整个会话唯一
- **禁止重复**：如果多个场景覆盖同一主题，必须变化视觉角度
- **约束语言**：如果图中有文字，prompt 必须指定语言
- **静态优先**：图用于静态概念，视频仅用于必须展示运动/过程时

这部分直接搬进我们的 `prompts/tutor_agent/system.yaml`。

### 4. PPT/TTS 方案代替视频生成（选搬⭐⭐）

不搬 OpenMAIC 的 7 个视频提供者（太重），也不搬 DeepTutor 的 Manim（太复杂）。

**用 PPT+TTS 方案做短视频：**
1. LLM 生成 PPT slides（OpenMAIC 的 slide-content 模板简化版）
2. python-pptx 渲染 PPT → 导出图片序列
3. OpenAI TTS 生成每页旁白音频
4. FFmpeg 合成图片+音频 → MP4

这是可控范围内最务实的「短视频讲解」方案，OpenMAIC 的 slide template 结构和 TTS adapter 模式可以借鉴。

## 四、关键设计决策

| 决定 | 选择 | 理由 |
|------|------|------|
| 图表方案 | Mermaid 优先 → SVG 次之 | Mermaid 文本即代码，LLM 原生支持，渲染零成本 |
| 图片生成 | DALL-E via OpenAI adapter | 已有 OpenAI key，不需要新接入 |
| 视频方案 | PPT+TTS+FFmpeg | 可控、可靠、34 天内可完成 |
| AI 视频 | **不做** | DeepTutor 的 Manim 需要 subprocess + GPU，OpenMAIC 的 7 个视频 API 太贵 |
| 质量保证 | DeepTutor 的 3 阶段 Review | 额外一次 LLM 调用换图表质量，值得 |

## 五、结论

**最大 ROI 的 3 件事（本周就做）：**
1. **Mermaid 内联生成** — 1 天实现，立即让所有答疑回答自带图解
2. **VisualizePipeline 3 阶段流水线** — 3 天实现，保证图表质量的核心机制
3. **OpenAI Image Adapter** — 2 天实现，解锁 AI 图片生成能力

这三件事做完，我们的系统就在多模态输出上有了真正的产品竞争力——不是「能画图」，而是「能画出对学习真正有帮助的图」。
