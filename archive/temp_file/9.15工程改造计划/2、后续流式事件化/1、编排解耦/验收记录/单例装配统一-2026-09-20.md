## 三、锁语义统一：定性为「纵深防御」，不是「修复竞态」

前 7 个工厂（`chat_center` / `tutor_center` / `exercise_center` / `resource_center` / `plan_center` / `graph_center` / `intent_extractor`）已有双检锁；11 个为裸 `if ... is None:`：

`profile_agent` / `tutor_agent` / `content_agent` / `exercise_agent` / `path_agent` / `mindmap_agent` / `code_agent` / `profile_workflow` / `path_workflow` / `inquiry_service` / `graph_service`

**⚠️ 必须如实说明**：当前 48 个端点全部是 `async def`，跑在事件循环单线程上；工厂体全程同步、**无 `await` 让出点**（已由 `ASM-S04` 固化为断言）。因此「检查 None → 构造 → 赋值」不会被交错，**无锁工厂并未真的重复构造过**。

本次补锁面向未来（异步初始化、多线程 worker、同步端点跑线程池），属**纵深防御加固**，**不是修复已观测到的缺陷**。这一条也解释了为什么「响应字节零变化」在本轮天然成立。

## 四、注入点冻结（本轮最重要的边界决策）

摸底发现既有 **11 个测试文件**把工厂与状态变量当作运行时注入点，分四类：

| 类别 | 内容 | 规模 |
|---|---|---|
| A | `monkeypatch.setattr(internal_api, "_get_xxx", ...)` | 8 个名字 / 25 处 |
| B | 直改模块级状态变量 `internal_api._xxx_singleton = stub` | 3 个变量 / 13 处 |
| C | `inspect.getsource(route)` 内的 `_get_xxx()` 字面文本断言 | 5 个文件 / 7 处 |
| D | `hasattr` 存在性锁（正向 2 / 负向 3） | 5 处 |

A 类明细：`_get_plan_center` 9、`_get_chat_center` 6、`_get_resource_center` 3、`_get_exercise_center` 2、`_get_inquiry_service` 2、`_get_path_workflow` 1、`_get_profile_workflow` 1、`_get_tutor_center` 1。
B 类明细：`_chat_center_singleton`（`test_sse_contract.py` ×3）、`_graph_service_singleton` + `_graph_center_singleton`（`test_graph_endpoints_api_contract.py` / `test_graph_endpoints_api_delegation.py`，**直接赋值**而非 monkeypatch）。

**结论：工厂不能搬离 `internal_api` 模块。** 搬到新模块后 A/B/C 三类共 38 处注入点会同时失效（端点从新命名空间取名后，`internal_api._get_x = stub` 变成空操作）。这正是记忆中已登记的遗留坑——`internal_api.extract_knowledge_nodes` 搬迁后失效、「新脚本必须双打两处注入点」。本轮**明确不重复该模式**，改为「同模块收敛」。

已在装配区块头部把这三条约束写成注释，并由 `ASM-C03` / `ASM-C04` 契约化。

## 十二、与第 5 步（拆 `internal_api/` 包）的衔接

**关键前瞻结论**：装配区块的最终归宿是 `internal_api/__init__.py`，**不是** `app/core/deps.py`。

理由即 §四：A/B/C 三类注入点都要求 `internal_api.<name>` 可读可写。拆包后 `internal_api` 成为包，`internal_api._chat_center_singleton = X` 设置的是**包 `__init__` 的属性**；若工厂体位于 `internal_api/deps.py`，它读的是 `deps` 自己的模块全局 → 注入点再次失效。

因此第 5 步应拆为：

```
internal_api/
├─ __init__.py     # 本轮的装配区块（状态 + _get_xxx）+ router 聚合
├─ tutor.py / resources.py / plans.py / ...
```

本轮把声明收拢成单一区块，客观上是为那次搬迁做的准备。反之若本轮拆到 `app/core/deps.py`，第 5 步就得再改一次那 38 处注入点——两轮各疼一次。
