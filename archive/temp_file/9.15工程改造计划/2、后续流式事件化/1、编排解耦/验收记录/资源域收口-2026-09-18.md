## 5. 异常、取消与降级 ✅ 通过

### 5.1 Workflow 抛异常（Case 3）

**机制**：注入 `center.resource_workflow.run = AsyncMock(side_effect=RuntimeError("boom"))`

**关键输出**：

```
========== CASE 3: workflow raises → error done ==========
HTTP 200
events: 1
done.data: {'error': '资源生成失败，请稍后重试'}
CASE 3 PASS
```

**Producer 异常处理链**（来自 `app/centers/resource_center.py:137-149`）：
- producer 内 `try/except Exception` 捕获
- `logger.error(..., exc_info=True)` 写完整 traceback 到日志
- 仍 yield `done_event({"error": "资源生成失败，请稍后重试"})` 到 queue
- consumer 收到 done 后正常退出，try/finally 清理 producer_task

控制台同步可见 producer traceback，确认异常路径走通 ✅

### 5.2 取消消费时后台 producer 兜底

由离线测试覆盖：

- `TestResourceCenterStreamGenerate.test_stream_generate_calls_workflow_run_once` — `assert_awaited_once()` 通过，说明 producer 与 consumer 协同无残留
- `TestResourceCenterStreamGenerate.test_stream_generate_workflow_exception_yields_error_done` — 异常时仍 yield 恰好一个 done
- `app/centers/resource_center.py:159-165` — `try/finally` + `producer_task.cancel()` + `await producer_task`（吞 CancelledError 与 Exception）

同进程 ASGI harness 中取消场景测试因 ASGITransport 的事件循环边界问题不便直接断言，留作离线测试保障。

- 不在本轮自动化范围
