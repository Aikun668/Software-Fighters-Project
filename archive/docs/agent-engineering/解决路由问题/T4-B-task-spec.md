## 2. 三个代码落点

### 2.1 复合识别与顺序（`plan_builder` + `semantic_router`）

- 复合表达式（"先 X 再 Y""X 然后 Y""顺便/外加/并/以及"）识别为多任务，不静默丢第二诉求。
- 顺序：**用户明确表达的顺序 > 业务约束**。用户说了"先讲解再出题"就按这个排；没说顺序才按业务约束（诊断/画像/计划先于出题/资源）。

### 2.2 数据依赖（`schemas` + `chat_task_dispatcher`）

- `CenterTask` 增加 `depends_on: list[int]`（依赖的 task 下标），`ExecutionPlan` 增加依赖图的构建/校验。
- Dispatcher 执行有依赖的任务时，把**上游的结构化结果**（`CenterResult.payload` 的必要键）注入下游 task 的 `context`，不做无边界长文本拼接。
- 无依赖任务保持现状（独立执行）。

### 2.3 跨轮指代消解（`semantic_router` 或新 `context_resolver`）

- 路由决策读 `context["messages"]`（history 已进得来，见 `internal_api/chat.py:40`），识别"再来5道/把图改详细/难度调高"这类指代，解析到最近一次同类产物。
- 指代找不到明确对象 → 安全追问（不误改其他产物）。

### 2.4 部分失败/追问/确认统一语义（`execution_gate` + Dispatcher）

- 中间任务失败：明确「继续后续独立任务 / 阻断有依赖的后继」。
- 追问/确认的结果（用户答了之后）能正确续上原计划，不重复生成。

## 4. 验收 Gate（对齐 master plan T4-B-Gate）

- [ ] 单条复合请求主要诉求不再被吞；执行顺序符合用户表达
- [ ] 无依赖任务独立执行；有依赖时下游确实拿到上游结果
- [ ] 多轮指代找到正确对象；找不到时安全追问、不误改其他产物
- [ ] 部分失败/追问/确认有一致结果，用户能理解实际完成了哪些任务
