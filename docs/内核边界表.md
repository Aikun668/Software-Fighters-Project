# Python Agent 内核 · 边界表

> 对应《简历沉淀总计划》**阶段 1** 交付项④（"记录内核边界：哪些依赖 Java，哪些纯 Python 自足"）。
> 结论依据：源码静态核查 + `scripts/demo_kernel.py` 实测（2026-10-09）。
> 维护提示：这张表是**演示与面试的边界依据**，改动内核依赖面时请同步更新。

---

## 一、一句话结论

**Python 内核可以完全脱离 Java / 前端 / MySQL / Redis / MinIO 独立运行。**
三条链路（资源生成、问答、编排事件流）均已在无 `.env`、无 API Key 的条件下实测跑通。

唯一的"外部依赖"是**本地文件与模型缓存**：知识图谱骨架 JSON（随仓库携带）
与 `sentence-transformers` embedding 模型（首次需下载，之后走本地缓存）。

---

## 二、依赖面总表

| 能力 | 依赖 Java？ | 依赖 MySQL/Redis/MinIO？ | 纯 Python 自足？ | 依据 |
|---|---|---|---|---|
| 服务启动（`main.py` → :8001） | 否 | 否 | ✅ | 全域 grep 零 `DATABASE_URL`/`aiomysql`/`sqlalchemy`；实测 `/health` 200 |
| 意图门控 + 路由（`auto` 模式） | 否 | 否 | ✅ | 实测 `resource` 场景 18 帧跑通 |
| 资源生成 + 质量门 | 否 | 否 | ✅ | 实测 `elapsed=46~270ms`，`final_status=success` |
| 流式事件（`run_id` + `seq` + 进度帧） | 否 | 否 | ✅ | 实测 14 条 `progress` 帧成对 |
| 问答 RAG（TutorAgent） | 否 | 否 | ✅ | 实测 69 token 流式正文；**需本地 embedding 缓存** |
| 知识图谱（骨架加载 / 补边 / 掌握度注入） | 否 | 否 | ✅ | 数据源是本地 `SKELETON_PATH` JSON，非数据库 |
| 向量检索（ChromaDB） | 否 | 否 | ⚠️ 本地持久化 | `chromadb.PersistentClient(path=CHROMA_PERSIST_PATH)`，写本地磁盘 |
| **掌握度落库 / 学习证据持久化** | **是** | 由 Java 侧承担 | ❌ | Java 负责 DB；Python 侧只接请求级入参 |
| **真实用户/会话数据** | **是** | 由 Java 侧承担 | ❌ | 前端 → Java → Python，Python 不持有会话存储 |

> 关键点：**"依赖 Java"的不是计算能力，而是数据来源。** 内核自己的全部推理、
> 编排、质量门、流式输出都不需要 Java；需要 Java 的只是"真实用户数据从哪来"。

## 三、实测记录（2026-10-09，mock 引擎）

测量环境：Windows，Python 3.12.7（Anaconda），**无 `.env`**，
`DEEPSEEK_API_KEY` / `MINIMAX_API_KEY` 均为空，`AI_SERVICE_MOCK_LLM=1`。

| 场景 | 端点 | 帧数 | 耗时 | 关键结果 |
|---|---|---|---|---|
| `resource` | `/internal/api/chat` | 18 | **163~250 ms** | 阶段 `plan→generate→validate→review→finalize`，5 内容块 |
| `resource_direct` | `/internal/resources/generate` | 13 | **16~51 ms** | 质量门 `review=skipped`，终态 `success`，5 内容块 |
| `tutor` | `/internal/api/chat` | 79 | **48.4 s 冷 / 5.1 s 热** | `retrieve→respond→analyze`，69 字流式正文 |

**复现性**：每个场景 `--repeat 2` 两次运行指纹**逐帧一致**（`resource` =
`c7b85e97…`，`resource_direct` = `cd75a9e0…`，`tutor` = `0ca89361…`）。

## 四、两个必须知道的坑（否则演示会翻车）

### 坑 1：问答场景冷启动慢，且**会在无网时等很久**

实测拆解（`import` 阶段，用 `HF_HUB_OFFLINE=1` 复测）：

| 环节 | 耗时 |
|---|---|
| `import torch` | 4.7 s |
| `import sentence_transformers` | **32.4 s** |
| `SentenceTransformer(...)` 构造 | 7.3 s |
| 首次 `encode()` | 1.5 s |

- 不设离线标志时，`tutor` 首次运行实测 **157 s**（在等 HF 检查模型更新，`HF_ENDPOINT=hf-mirror.com`）；
- 加 `HF_HUB_OFFLINE=1` 后降到 **32 s**；
- 第二次运行（进程内缓存已热）稳定在 **~5 s**。

**结论**：演示默认走 `resource` 场景（不加载 embedding）。若必须演示问答，
先预热或用 mock，**不要在现场第一次运行时加载模型**。

### 坑 2：mock 引擎生成的正文内容质量有限

mock 不调用真实模型，`ResourceGenWorkflow` 会把**输入的整个句子**当主题，
产出形如"给注意力机制生成一套学习资源核心概念"的标题。

**演示取舍**：
- 要展示**编排结构**（哪个 Agent、哪些阶段、质量门、流式帧）→ mock 足够，且秒级、可复现；
- 要展示**内容质量** → 必须 `--mode real` + 配置真实 Key。
