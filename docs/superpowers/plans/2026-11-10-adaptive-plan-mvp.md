# 动态学习计划 MVP：模块设计与固定验收

用户选择方案二并授权直接实施，文档无需先行审批。基线：741292e。使用现有 Vue/Java，不新增向量库或另一个 Agent 框架。

## 设计
1. 独立持久化计划：目标、模块、小任务；只展示近期 1–3 个未完成任务。完成表示用户自报，不推断掌握。
2. 断点：任务状态（待做、进行中、暂停、卡住、完成）、已到哪里、下一步。刷新后恢复。
3. 局部调整：聊天描述时间/卡点，形成可审阅的保留、拆分、延期差异，不直接保存。MVP 明示规则驱动而非假装通用语义理解。
4. 确认与历史：确认后持久化，版本冲突拒绝覆盖，已完成任务不可在调整中丢失。最近一次调整可撤销；后续进度产生后禁止覆盖式撤销。
5. 期限冲突：剩余估时与可用时间比较，明确展示并要求选择，不暗改目标。学习地图关联不等于先修关系。

## 实现边界
- 新 AdaptivePlanService/Controller：JdbcTemplate JSON 文档、所有权、版本、提案及撤销。
- 前端 adaptivePlans API、LearningPlanPage 及复用聊天调整组件；旧快照入口保留。
- 不自动提醒、不新增测试账号、不改用户原有工作区、不推送。

## 固定验收门槛
- 全新计划无虚构预置数据；创建后重新读取字段一致。
- 下一步任务数量为 0–3，全部来自真实未完成任务。
- 暂停/卡住/续学/完成四种转移及断点重读均通过。
- 任何提案在确认前计划版本和任务不变；取消不变；重复确认不重复生效。
- 拆分前后未完成工作总估时保持，完成项 ID/状态/内容保持。
- 期限冲突未经明确选择不得保存。
- 旧版本写入及跨用户读取/修改/应用/撤销拒绝。
- 撤销恢复调整前状态；有后续进度时拒绝旧撤销。
- 前端类型检查、生产构建、相关及全量可运行测试通过；后端相关及可运行回归通过。
- 独立代码审查后修复重大问题；浏览器覆盖创建→暂停→调整→确认→刷新→续学，检查桌面和窄屏，无假成功。若真实服务环境不可用，明确报告替身边界而非宣称生产验收。
