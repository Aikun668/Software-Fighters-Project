# 动态学习计划 MVP 交付

基线 `741292e`；本地开发分支 `feat/adaptive-plan-mvp`。本记录为开发验收记录；GitHub 发布在后续独立审核通过后执行，发布状态另行确认。不部署、不触碰用户电脑原工作区。

## 已实现闭环

目标 → 模块 → 近期最多 3 步 → 保存进度/断点 → 中断后续学 → 情况变化先预览局部调整 → 确认保存 → 刷新重读同一计划。

- 未来模块可稍后添加小任务；延期任务可重新列入。
- 计划页和真实聊天页复用同一个计划组件、同一后端接口。
- 继续学习将真实目标/任务/断点生成一次性草稿，不自动发送。输入框是版本化快照，不随面板改动自动覆盖；可点“用最新计划准备续学草稿”保留原输入并追加最新版本。
- 拆分保持工作量，不丢已完成项。完成仅是用户自报，不写成知识掌握。
- 期限不可能时显示持续警告。延长期限/延期部分任务的确切结果在确认前展示。
- 服务端所有权、乐观版本保护；重复确认不重复应用；撤销不覆盖后续进度；跨日期提案须重新预览。

## 实现取舍与边界

本版是透明规则驱动的局部调整，识别有限预算、拆分、卡点和延期表达；用户可指定任务。不支持的/否定式请求拒绝猜测。不是通用大模型自动排程，也没有自动提醒。

新模块使用 `adaptive_plan`、`adaptive_plan_proposal`，沿用现有 JDBC 数据库连接并首次访问建表，需要相应数据库权限。历史 research 模式生成的旧计划没有自动迁移或双向同步，界面明确分开；不能把旧模型生成回复说成已修改新计划。记忆与知识图谱没有被当成学习完成证明。

## 不夸大的验收范围

浏览器使用生产构建 + 生产 Java Controller/Service + H2 SQL，测试身份和其他非计划 API 空响应。不是静态假计划，但也不是生产登录/MySQL/Redis/MinIO/真实 LLM 全链路。未连接用户实际网关，未声称已上线。H2重连与刷新通过，不等于生产进程重启验证。

本版可以按提供脚本复验代码和流程；用户真实环境验收仍需有效数据库/登录与网关配置。

## 本人验收路线（接上现有网关后）

1. 打开「学习计划」(`/learning-path`)，创建事务学习目标，当前模块写一个 45 分钟任务，再留一个空的远期模块。
2. 记录“读到幻读定义”与“开两个事务跑例子”的断点，暂停并刷新。
3. 输入“每天只有20分钟”，先看拆分预览，取消一次确认原计划不变；再预览并确认，刷新检查。
4. 带着计划去对话，检查草稿中的版本与断点；聊天页展开动态计划，修改后用最新计划准备草稿，不会自动发出。
5. 完成一小步，在远期模块新增下一任务；延期任务可重新列入。尝试刚确认后撤销，再尝试保存新进度后撤销，后者必须拒绝覆盖。
6. 设置无法容纳剩余工作量的截止日，核对准确延期日期或延期任务清单后才确认。
