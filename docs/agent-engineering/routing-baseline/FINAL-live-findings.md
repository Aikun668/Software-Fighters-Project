## Bug 1（误触发 PLAN 被吞）：「希望你写一个计划」判成 EXERCISE

**会话 104** 用户原话：

> 我现在准备睡觉了，但是希望你**写一个计划**，因为明天要做很多很多**题**，所以我想有顺序地做

**实际路由**：`EXERCISE`（`capability_evidence:verb_topic_exercise`）→ 生成了 3 道 ML 练习题。
**用户真实诉求**：写一个学习计划（PLAN）。

**两个独立缺陷**：

| # | 缺陷 | 证据 |
|---|---|---|
| 1a | `make_plan` 规则动词表缺「写」 | `"写一个学习计划"` → NORMAL_CHAT（漏判）；`"帮我安排一下明天的复习"` → NORMAL_CHAT（"安排"命中但产物词"复习"不在表内） |
| 1b | `verb_topic_exercise` 把**陈述**当**请求** | `"因为明天要做很多很多题"` → EXERCISE；`"明天要做很多题"` → EXERCISE；`"我想有顺序地做题"` → EXERCISE。这是**描述**不是**祈使**，却命中"做…题" |

→ 结果：句中"要做很多题"这个**从句**把整句路由劫持成了出题。

## Bug 2（中文数量词不认）：「生成**一道**高数题」给了 3 道

**会话 98** 用户原话：

> 帮我生成**一道**高数题，很难的那种，给人工智能测试的那种

**实际**：生成 3 道。用户下一轮抱怨「不是说1道就够了吗？你怎么给我生成了3道啊」。

**根因**：`COUNT_PATTERN = re.compile(r"(\d+)\s*[道个题张卡]")` **只认阿拉伯数字**。

| 输入 | COUNT_PATTERN | 最终 count |
|---|---|---|
| 帮我生成**一道**高数题 | `[]` | **3（默认）** ❌ |
| 帮我出**5**道题 | `['5']` | 5 ✅ |
| 给我**一道**题 | `[]` | **3（默认）** ❌ |
| 出**3**道选择题 | `['3']` | 3 ✅ |

→ 中文数字（一/两/三/…/十）全部落到默认值 3。
